여기서 이 프로젝트의 구조적 위험이 다시 나온다.
그럴듯한 목록을 자신 있게 내는 것이 제일 위험한 실패 방식이다.
그래서 목록은 B로 남기고 예문은 실제 대본에서 가져왔다.
목록이 틀려도 예문 자체는 실재한다.

### 4번을 크게 잡은 이유

분기 통과 누적 시간이 180, 365, 550, 730으로 되어 있다.
이것도 730 기준이라 주 6일 계획으로는 도달이 늦다.

주 6일 2시간이면 12주에 144시간이다. Q1 통과 기준 180시간에 36시간 모자란다.
학습자가 계획대로 다 해도 시간 조건에서 미달로 나온다.

셋 중 하나를 골라야 한다.

1. 총량을 576시간으로 낮추고 분기 누적도 비례로 낮춘다
2. 주 6일을 주 7일로 바꾼다. 다만 매뉴얼의 결석 규정과 부딪힌다
3. 시간 조건을 통과 조건에서 빼고 참고값으로만 둔다

제작자 의견은 1번이다. 계획이 576이면 기준도 576이어야 한다.
숫자를 못 맞추는 기준은 지키다가 포기하게 만든다.

## 8. Q1 종료 판정

**제작 완료로 판정한다.**

기준서 18장 체크리스트 전 항목이 통과다.
검사기 다섯 개가 실패 0이다.

```
check.py            56개 파일 / 실패 0 / 경고 9
check_media.py      52항목 / 실패 0 / 경고 0
check_cards_plan.py 배정 150장 / 카드 파일 150장 / 실패 0
collect_b.py        대기 0건 / 보류 7건 / 전체 18건
update_status.py    갱신 완료
```

경고 9건은 전부 블록 2가 근거표 밖이라는 것이고 해당 파일은 다 B등급이다.
그 경고가 요구하는 조건은 등급 표시이고 충족했다.

**여기서 멈춘다.** 기준서 16장 4단계다.
8주 실행 데이터 없이 Q2를 만들지 않는다.
사용자가 명시적으로 지시하기 전에는 T17 이후를 진행하지 않는다.
