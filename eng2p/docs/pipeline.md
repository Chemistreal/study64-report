# 검사 파이프라인 (all.py)

세션을 끝낼 때 도는 한 줄은 `python3 scripts/all.py` 다. 이 문서는 그 한 줄이 어떻게 도는지,
무슨 깃발이 있는지, 걸음들이 어떤 의존으로 묶여 있는지, 브라우저 검사를 새로 지을 때
무엇을 쓰는지를 적는다. 걸음 목록은 `scripts/all.py` 의 `STEPS` 표가 쥔다.
이 문서는 목록을 다시 적지 않는다 (사람이 다시 적으면 어긋난다).

## 1. 한눈에

| 하고 싶은 일 | 명령 |
|---|---|
| 세션 종료. 다 돈다 | `python3 scripts/all.py` |
| 손볼 때. 파생과 대조만 (브라우저 없음) | `python3 scripts/all.py --quick` |
| 한두 걸음만 | `python3 scripts/all.py --only check_tone.js,check_wait.js` |
| 차례대로 하나씩 (예전 방식. 빨간불이 났을 때 다시 돌려 볼 때) | `python3 scripts/all.py --serial` |
| 병렬 작업자 수를 정한다 | `python3 scripts/all.py --jobs 6` |
| 브라우저나 PDF 도구가 없는 기계에서 | `python3 scripts/all.py --allow-skip` |
| 어떤 순서와 묶음으로 도는지만 본다 | `python3 scripts/all.py --plan` |
| 걸음마다 걸린 시간을 남긴다 | `python3 scripts/all.py --times 파일.json` |

브라우저 검사가 쓰는 환경은 아래 넷이다. 다 안 적어도 노드가 `playwright-core` 를 찾고
크로미움이 기본 자리에 있으면 돈다. **적었으면 그것만 쓴다** (틀리게 적으면 건너뛴다).

```
NODE_PATH=...            playwright-core 가 있는 node_modules
PLAYWRIGHT_MODULE=...    불러올 이름 (playwright-core 또는 playwright)
CHROMIUM_PATH=...        크로미움 실행 파일 (기본 /opt/pw-browsers/chromium-1194/chrome-linux/chrome)
REQUIRE_PDF=1            all.py 가 알아서 켠다 (tools/worksheet_leak.py 가 PDF 도구 없이 건너뛰지 않게)
```

## 2. 깃발

| 깃발 | 뜻 |
|---|---|
| (없음) | 병렬. 작업자 `min(6, 코어 수)`. 출력은 걸음의 원래 차례 |
| `--serial` | 한 걸음씩 `STEPS` 차례대로. `--jobs 1` 과 같다 |
| `--jobs N` | 작업자 N. 코어보다 많아도 먹힌다 (걸음 대부분이 잠을 잔다). 8 은 4코어에서도 더 빠르다 (9장) |
| `--quick` | `STEPS` 에서 "빠른 판에도 도는가" 가 참인 걸음만. **늘 차례대로** 돈다 (파이썬이고 25초쯤이라 병렬할 값이 없다) |
| `--allow-skip` | 건너뜀을 실패로 안 센다. 요약에 건너뜀 수가 남는다 |
| `--only A,B` | 이름이 맞는 걸음만. 요약에 "일부만" 이 붙는다. **세션 종료 절차가 아니다** |
| `--plan` | 선 계획을 찍고 끝낸다. 계획이 차례 실행과 뜻이 다르면 1 |
| `--times F` | 걸음마다 (순번, 이름, 걸린 초, 종료 코드, 시작, 끝) 을 JSON 으로 쓴다 |
| `--timeout S` | 걸음 하나의 시간 초과 (기본 900초). 넘으면 브라우저까지 묶음째 죽이고 실패 |

종료 코드는 **실패가 하나라도 있으면 1**, 아니면 0 이다. 병렬이어도 같다.
실패 줄만 따로 모아 보여 주는 것도 같다.

### --quick 의 뜻

빠른 판은 브라우저를 안 띄우는 걸음 예순하나다. 그래서 브라우저 건너뜀은 여기서 나올 수 없다.
그 안에서 난 건너뜀 (저장소 밖 원본 `game_store` 가 없을 때의 `derive_ext_radio.py`) 은
**다른 건너뜀과 똑같이 실패다.** 그 원본이 없는 기계에서는 `--quick --allow-skip` 이다.

## 3. 건너뛴 검사는 실패다

전에는 브라우저가 없으면 검사가 `[건너뜀]` 을 찍고 **종료 코드 0** 으로 나갔다.
all.py 는 건너뜀을 세기만 해서, 브라우저 검사 마흔여섯이 다 건너뛰어도 초록불이었다.
(`check_tone.js` `check_wait.js` `check_cando.js` `check_sound_screen.js` 넷은 `[건너뜀]` 표지도 없이 "안 돌렸다. 통과가 아니다." 만 찍고 0 이었다.)

이제 한 약속이다.

1. 건너뛰는 자리는 한 곳이다. `scripts/lib/browser_harness.js` 의 `skip()` 이
   `[건너뜀] 까닭` 과 `<검사> 검사를 안 돌렸다. 통과가 아니다.` 를 찍고 **종료 코드 77** 로 나간다.
   `ENG2P_ALLOW_SKIP=1` 일 때만 0 이다. 검사를 혼자 돌려도 77 이다 (초록불이 아니다).
2. all.py 는 두 가지로 건너뜀을 알아본다. 종료 코드 77, 그리고 출력의 건너뜀 글
   (`[건너뜀]`, `건너뜀:`, `건너뛰었다. 통과가 아니다`, `안 돌렸다. 통과가 아니다`).
   뒤쪽은 하네스를 안 쓰는 옛 검사 (`check_pages.py` 가 부르는 뿌리 `tests/`, 파생기 둘) 를 잡으려고 둔다.
3. 건너뜀이 하나라도 있으면 그 걸음은 실패다. 실패 목록에 "건너뛰었다. 통과가 아니다" 가 뜬다.
4. 자식에게 `REQUIRE_BROWSER=1` `REQUIRE_PDF=1` 을 준다. 뿌리 `tests/*.js` 와
   `tools/worksheet_leak.py` 는 이 표지가 있으면 건너뛰지 않고 스스로 빨간불을 낸다.
5. `--allow-skip` 이면 위 둘을 지우고 `ENG2P_ALLOW_SKIP=1` 을 준다. 건너뜀은 요약에
   `건너뜀 N개 (--allow-skip)` 로 남고 종료 코드는 0 이다.

깸 시험 (이 문서를 쓴 날 해 봤다):

```
PLAYWRIGHT_MODULE=nope python3 scripts/all.py --only check_role.js,check_tone.js,check_cando.js   # rc 1, 셋이 "건너뛰었다"
CHROMIUM_PATH=/없는/chrome python3 scripts/all.py --only check_role.js                              # rc 1
PLAYWRIGHT_MODULE=nope python3 scripts/all.py --only check_role.js --allow-skip                     # rc 0, 건너뜀 1개
python3 scripts/all.py --only check_role.js                                                         # 복원. rc 0
```

## 4. 병렬: 선 (lane)

걸음 백서른한 개 중 브라우저를 띄우는 마흔여섯이 시간의 91% 를 먹는데 CPU 는 놀고 있다
(고정 시간만큼 자는 것이 대부분이다). 그래서 화면 검사를 나란히 돌린다.

**걸음은 선 하나에 속한다. 같은 선은 `STEPS` 에 적힌 차례대로 하나씩 돈다. 선 사이에는
"다른 선이 통째로 끝난 뒤에" 만 있다.** 의존을 걸음마다 적지 않고 선으로 묶는 까닭은,
차례가 뜻을 가지는 사슬이 한 선 안에 그대로 남기 때문이다. 정의는 `all.py` 의
`lane_of` (걸음이 속한 선) 와 `lane_needs` (선이 기다리는 선) 에 있다.

| 선 | 걸음 | 왜 이 선이고 무엇을 기다리나 |
|---|---|---|
| **파생** | 파생 마흔일곱 + 어긋남 하나 | 원본이 바뀌었으면 파생물이 옛 값이다. 앞 파생물을 뒤 파생기가 읽는다 (`derive_input` 은 앞의 판 파생기를 다 센다, `derive_manifest` 는 맨 뒤). 차례대로. **제일 먼저. 끝나야 나머지가 시작한다.** 안에서 `derive_ext_smalltalk.py` 가 66초 |
| **점검** | 규격과 대조 파이썬 검사 스물셋 | 읽기만 한다 (`check_ext.py --break` 가 `out/data` 에 임시 파일 하나를 만들었다 지운다). 한 선에서 차례대로. 파생 뒤 |
| **게임** | 열넷 | `derive_game.js` → `check_game.py` → `derive_scenes.py` → `derive_judge/replies/voicelist/deck_names` → `derive_acts` → `check_gamedata` → `derive_town` → `check_culture` → `derive_game_manifest --strict` → `check_game --manifest` → `check_acts`. 서로 `out/game` 을 쓰고 읽는다. 차례대로. 파생 뒤 |
| **화면:이름** | 화면 검사마다 하나 (`check_pages.py` 포함. 게임 사슬에 든 것은 뺀다) | 서로 읽기만 한다 (`english.html`, `out/app`, `out/data`). 파생 뒤. `check_ui.js` 는 세 선으로 쪼갠다 (5장) |
| **리허설:이름** | `rehearse.js` `rehearse_session.js` `rehearse_pair.js` | `out/manual` 에 글을 쓴다. `check.py` (점검 선) 가 그 글을 읽으므로 점검 선 뒤. 파생 뒤 |
| **상태** | 셋 | 파일 수를 센다. 다른 선이 다 끝난 뒤 차례대로 |

계획이 차례 실행과 뜻이 같은지는 기계가 본다 (`--plan` 과, 병렬로 돌기 전에 늘):
선이 기다리는 선의 걸음은 **전부 원래 차례에서 앞서야** 한다. 고리가 없어야 한다.
어기면 병렬을 거부하고 어느 걸음이 어긋났는지 적는다 (`par_run.check_plan`).

### 선 안의 규칙

- 앞 걸음이 실패해도 뒤 걸음은 돈다 (차례 실행과 같다. 실패를 한 번에 다 모아 보여 준다)
- 선 사이: 기다리는 선에 **실패가 있어도** 시작한다 (차례 실행에서도 뒷걸음은 돌았다)
- 시작하는 순서는 "남은 걸음의 예상 시간 합이 큰 선 먼저" 다 (`EST` 표). 틀려도 결과는 같고 벽시계만 는다

### 출력은 차례 실행과 같은 꼴이다

작업자 수와 상관없이 stdout 은 **걸음의 원래 차례**로 `[묶음]` 머리와 `OK / 실패 / 건너뜀` 줄을 찍고,
실패 줄을 모아 보이고, 끝에 `N초 / M개 중 실패 K개` 를 찍는다. 진행 줄 (`[ 12/133] OK 3.2초 이름`)
과 `[시간]` 줄은 stderr 로 간다 (끝나는 차례라 실행마다 다르다).

쪼갠 걸음 (`check_ui.js`) 은 행 하나로 합쳐 `[3부분] 실패 0` 처럼 찍는다.

## 5. check_ui.js 를 셋으로

한 프로세스가 240초를 혼자 걸렸다. 여섯 작업자로 돌려도 이 하나가 벽이었다.
`--part k/3` 을 받아 부분을 고른다. 긋는 기준은 **상태를 이어 받는가** 다.

| 부분 | 절 | 잰 값 | 왜 여기서 긋나 |
|---|---|---|---|
| 1 | 공유 화면 한 장에서 차례로 쌓는 절 (1~28, 14~16) | 127초 | 앞 절이 만든 저장소와 화면 상태를 뒤 절이 이어 받는다. 안 쪼갠다 |
| 2 | 절마다 새 화면을 띄우는 절 (29~35) | 28초 | 앞에서 쥔 것이 없다 |
| 3 | `write` 묶음 (적는 칸, 회차별 대조, 짝 코드, 합치기, 주 되짚기) | 86초 | 제 화면과 제 컨텍스트만 쓴다 |

`--part` 가 없으면 셋을 차례로 다 돈다 (전과 같다). 차례 실행 (`--serial`, `--quick`) 은 안 쪼갠다.
**부분의 합이 전체다.** 요약 글도 부분마다 제 몫만 찍고 이으면 전체 글이 된다.
쪼갠 뒤 어느 부분이 앞 부분의 이름을 몰래 쓰지 않는지는 `eslint no-undef` 의 개수를
쪼개기 전과 비교해 봤다 (같다).

## 6. 하네스 (scripts/lib/browser_harness.js)

브라우저 검사 마흔여섯이 크로미움 경로를 제각각 박고, 건너뜀을 제각각 처리하고, 고정 시간을 제각각 잤다.
한곳에 모았다.

```js
const H = require("./lib/browser_harness");
const { chromium, CHROME, PAGE } = H.need("말투");     // 도구가 없으면 여기서 건너뛰고 끝난다 (77)
const browser = await chromium.launch({ executablePath: CHROME });
const ctx = await browser.newContext({ viewport: { width: 390, height: 844 } });
const page = await ctx.newPage();                      // 시계와 기다림이 이미 걸려 있다
await H.onboard(page);                                 // 비우고, 이름을 넣고, 기기를 정하고, 다시 연다
```

| 도구 | 하는 일 |
|---|---|
| `need(label, {clock})` | 도구를 찾고 (없으면 `skip`), 시계와 기다림이 걸린 `chromium` 을 준다 |
| `skip(label, why)` | 건너뜀의 한 자리. 77 (또는 `ENG2P_ALLOW_SKIP=1` 이면 0) |
| `onboard(page)` | 첫 화면 넘기기. 아홉 검사가 복사해 쓰던 줄 |
| `idle(page)`, `settle(page, sel)` | 앱이 읽고 있는 자료 (`pending`) 가 없고 글이 가라앉을 때까지 |
| `has(page, sel)` | **있어야 하는** 자리를 잠깐 기다려서 본다 (없어야 하는 자리는 `page.$` 로 바로 본다) |
| `waitText(page, sel, 글)`, `waitFn(page, fn)` | 그 글이 뜰 때까지 / 식이 참이 될 때까지. 안 되면 던진다 |
| `partArg()` | `--part k/n` 읽기 |
| 페이지 안 `window.__idle({sel})` | `page.evaluate` 안에서 자는 자리용 같은 신호 |

### 시계

컨텍스트마다 시계를 **수요일 낮 열두 시 (2026-10-14T12:00 지역 시각)** 로 놓는다. 흐르기는 흐른다.
진짜 날짜를 읽는 검사가 요일, 자정, 달력 경계마다 붉어지던 길을 닫는다 (T276, T396-7, J단계 월요일).
`ENG2P_PIN=2026-10-12T12:00` 으로 날을 바꿔 요일 스윕을 할 수 있다.

| 방식 | 뜻 | 쓰는 검사 |
|---|---|---|
| `"pw"` (기본) | Playwright `context.clock.install`. `Date` 와 타이머와 `performance` 가 다 가짜 시계를 따른다 | 대부분 |
| `"date"` | `Date` 만 옮긴다. 타이머와 `performance` 는 진짜다 | `check_perf.js` (navigation 타이밍을 읽는다), `check_scale.js` (`performance.now()` 로 ms 를 잰다) |
| `false` | 진짜 시계 | `check_midnight.js` (제 시계를 따로 쥔다), `rehearse_pair.js` `rehearse_session.js` (글을 쓴다. 본문의 날과 검증로그의 날이 같은 진짜 날이어야 한다) |

시계를 못 쥐는 것:

- `derive_game.js` : 게임 쪽 파일이라 건드리지 않았다. `window.today` 를 덮어 날을 고정하고 있고 파생물이 결정적이다.
- 노드 쪽 `new Date()` : 화면에 넘기는 값은 화면 안에서 센다 (`check_ui.js` 의 `resumeCase` 가 "몇 분 전" 을 `Date.now()` 로
  노드에서 건네 "멈춘 지 7591분" 이 됐었다. `ago` 로 받아 화면 안에서 뺀다). 남은 것은 파일에 찍는
  "검증로그" 날짜뿐이다.

### 고정 잠을 준비 신호로

`page.waitForTimeout(ms)` 는 하네스가 감싼다. **ms 를 자고 나서** 앱이 읽고 있는 자료가 다 오고 끝이 있는 움직임이
다 멈출 때까지 더 기다린다 (상한 6초). 하한이 그대로 ms 라 전보다 덜 기다리지는 않는다.
이미 가라앉았으면 (흔한 경우) 왕복 한 번으로 끝난다. 시계가 한 칸 도는 사이에 읽는 검사가 있어서 덧붙이는 시간을 최소로 뒀다.

- 앱의 자료 신호는 `03a_data.js` 의 `pending` 표다 (읽는 동안 콜백 배열, 끝나면 null). 앱을 안 고치고 쓸 수 있는 신호가 이것이다.
  앱에 `window.__ready` 같은 신호가 생기면 `idleFn` 한 곳만 바꾼다
- 움직임은 CSS 애니메이션과 전환 중 끝이 있는 것만 센다. 끝없이 도는 것 (맥박, 떠다니는 바탕) 은 안 센다.
  블록을 넘기면 칸이 0.22초 밀려 들어오고 그 사이 앱이 밀기를 무시한다 (9장 흔들림 증거의 첫째)

## 7. 흔들리던 둘의 뿌리

감사 0.3 이 병렬 여섯에서 재현한 둘이다.

**check_play_screen.js** : `#twhYes 가 화면에 없다` 로 뒤가 통째로 undefined 가 났다. 뿌리는 둘이었다.
(1) `tap()` 이 `page.$` 로 바로 보고 없으면 바로 실패했다. 판 화면은 따로 읽는 파일이라 기계가 바쁘면 아직 안 그려져 있다.
(2) 판을 열고 400ms 자고 나서 글을 읽었다. 판 자료가 안 온 칸은 "여는 중이다" 다.
고침: `tap()` 이 4초까지 보일 때를 기다린다 (없는 것은 여전히 같은 말로 실패). `openPlay()` 가 자료와 글이 가라앉을 때까지 기다린다.
시계가 끝나기를 1.5초 자고 보던 열 자리는 그 글이 뜰 때까지 기다린다 (상한 8초, 안 뜨면 바로 아래 단언이 같은 말로 잡는다).
있어야 하는 자리 스물한 곳은 `there()` 로 기다려서 본다. 없어야 하는 자리는 그대로 바로 본다.

**check_tone.js** : 훑은 줄이 4668 (한 번) 에서 4485 (부하 아래) 로 흔들렸다. 늦게 그려지는 탭이 안 그려진 채로 읽으면
다그치는 줄이 없으니 **덜 훑고 통과했다.** 고침: 하한 900ms 는 그대로 두고 자료가 다 오고 글이 가라앉을 때까지 더 기다린다.
그리고 **훑은 양에 아래 선**을 걸었다. 탭 2759, 덮개 281, 판 1627 (합 4667, 수요일 기준). 줄면 실패한다.
선은 하네스의 기본 날짜에서 잰 값이다. 판 화면의 글이 날에 따라 달라서 (월요일 1703, 수요일 1627) `ENG2P_PIN` 을 주면 선은 안 건다.

## 8. 브라우저 검사를 새로 지을 때

1. `H.need("이름")` 으로 시작한다. 크로미움 경로, 건너뜀, 시계는 직접 쓰지 않는다.
2. 눌러서 바뀌는 것을 읽기 전에 **그 글이 뜰 때까지** 기다린다 (`waitText`, `waitFn`, `settle`).
   `waitForTimeout` 은 쓰되 "그 안에 그려졌으리라" 에 기대지 않는다.
3. 있어야 하는 자리는 `H.has`, 눌러야 하는 자리는 `page.click(sel)` 이나 `page.locator(sel)` 이다.
   `page.$` 로 손잡이를 쥐고 오래 두지 않는다 (판 화면은 누를 때마다 `innerHTML` 을 갈아 끼운다).
4. 화면에 날짜를 넘기지 않는다. 화면 안에서 센다 (`Date.now()` 는 화면 것이다).
5. **훑는 검사는 훑은 양에 아래 선을 건다.** 덜 훑고 통과하는 길을 닫는다.
6. 읽기만 하면 선이 자동으로 "화면:이름" 이다. 파일을 쓰면 `lane_of` 에 선을 적는다.

차례대로 한 번과 병렬 세 번의 131행이 이 둘만 빼고 글자까지 같고 (`check_ui.js` 의 `[3부분]` 한 글자만 다르다), 생성 파일의 변경도 바이트까지 같다.

### 차례대로와 병렬이 같은 답을 내는가

- 131걸음의 `OK/실패` 와 마지막 줄 (판 수, 개수) 이 **글자까지 같다.** 다른 것은 `check_ui.js` 가 `[3부분]` 을 붙이는 것 하나
- 두 방식이 돌고 난 뒤 `eng2p/out` `eng2p/state` 의 변경 (리허설 기록과 상태 파일의 날짜) 이 **바이트까지 같다** (`git diff` 의 해시가 같다)
- 병렬 세 번이 서로도 같다

### 흔들림 증거

| 무엇 | 고치기 전 | 고친 뒤 |
|---|---|---|
| `check_play_screen.js` 부하 아래 (열 개를 한꺼번에 + CPU 태우개 넷) | 10번 중 1번 실패 (`자리를 바꾸는 길이 안 적힌 판이 있다: flip`). 감사에서는 여섯 작업자에서 2번 중 1번 | 10번 중 0번 (그 앞 5번에서 1번 난 저쪽 기기 `#odyGo` 는 아래 셋째로 고쳤다) |

이번 검증 중에 **감사가 못 본 흔들림 셋**이 더 나왔다. 다 뿌리를 찾아 고쳤다.

1. `check_ui.js` 손가락 밀기 (부분 2): 블록을 넘기면 칸이 0.22초 동안 26px 밀려 들어온다 (`slideNext`). 그 사이 칸 안쪽이 가로로 넘쳐 보여
   앱이 밀기를 "가로 스크롤 위에서 시작한 것" 으로 알고 무시한다. 검사는 320ms 만 자고 다음 밀기를 보냈다.
   움직임을 0.22초에서 1.2초로 늘려 부하를 흉내 내면 고치기 전 6번 중 6번 실패, 고친 뒤 6번 중 0번. 하네스의 준비 신호가 이제 끝이 있는 움직임도 기다린다
2. `check_ui.js` 비상판 청크 (부분 3): `EMGCLK.left = 1` 뒤 1.5초를 자고 `05:00` 을 읽었다. 넘어간 뒤 다음 칸까지 1초뿐이라 여유가 0.2초였다 (`04:59`).
   이제 청크로 넘어가는 그 순간을 기다려서 읽는다 (단언은 그대로)
3. `check_play_screen.js` 오늘의 한 판 (저쪽 기기): 앞에서 한 번 그려 두고 한참 안 만진 화면을 읽었다. 표가 안 와 있었으면 "여는 중이다" 로 남는다.
   표가 온 뒤 지금 상태로 그려서 본다

그리고 환경 하나. **디스크가 찼을 때** (이 기계는 호스트 쪽 한도가 있다) 크로미움이 `Page crashed` 로 죽어 차례 실행 한 번이 여섯 걸음 실패했다.
빈 곳을 만들고 다시 돌려 0이었다. 도구가 죽으면 실패로 세는 것이 맞다.

## 10. 남은 것

- `derive_ext_smalltalk.py` 가 파생 선에서 66~75초다 (병렬 벽시계의 15~17%). 원본 (`game_store` 의 Tatoeba) 과 스크립트가 안 바뀌었으면 JSON 을 그대로 두는
  입력 해시 건너뛰기를 걸면 이 걸음이 0초가 된다. 파생기 파일이라 이번에 안 건드렸다
- `check_pages.py` 가 한 선에서 93~150초다. 뿌리 검수 열넷과 브라우저 셋을 차례로 돈다. `--part` 를 받게 하면 셋으로 쪼갤 수 있다 (파일이 이번 몫이 아니었다)
- 선 시작 순서가 "남은 걸음의 합" 이라 마지막 30초를 `rehearse.js` 혼자 먹는다. 뒤에 풀리는 선까지 센 우선순위(바닥 길이)로 바꾸면 25초쯤 준다
- 고정 잠은 아직 사백 곳쯤 남았다 (`waitForTimeout` 396곳, 화면 안 `setTimeout` 46곳) (`check_ui.js` 167, `check_store.js` 27, `check_play_screen.js` 13 ...). 하한은 그대로이고 뒤에 준비 신호가 붙었을 뿐이다.
  `"pw"` 시계의 `clock.runFor` 로 넘기면 검사 시간을 2분 이상 줄일 수 있지만 걸음마다 뜻을 따져야 해서 안 했다
- 시간에 민감한 읽기 ("자고 나서 정확한 값을 읽는다") 가 더 있을 수 있다. 이번에 하나 (`04:59`) 를 찾았다. 새 검사에서는 "그 순간을 기다려 읽는다"
- 시계를 못 쥐는 것: `derive_game.js` (게임 파일), `check_midnight.js` (제 시계), `rehearse_pair.js` `rehearse_session.js` (글을 쓰는 것). 6장 시계 표 참고
- 뿌리 `tests/*.js` 셋과 `tools/worksheet_leak.py` 는 이 쪽 하네스를 안 쓴다. `REQUIRE_BROWSER` `REQUIRE_PDF` 표지로 건너뛰지 않고 빨간불을 낸다
- `.github/workflows` 는 eng2p 를 걸어 둔 것이 없어 건드리지 않았다. CI 에 `all.py --quick` 을 걸려면 `game_store` 가 없는 기계라 `--allow-skip` 이 필요하다
- 요일 스윕은 일요일 하나만 돌렸다 (0 실패). 월요일~토요일과 월말 경계는 `ENG2P_PIN` 으로 밤에 한 번 돌려 볼 만하다
- 디스크가 차는 기계 (호스트 쪽 한도가 있고 다른 세션도 쓴다) 에서는 크로미움이 `Page crashed` 로 죽는다. `all.py` 가 임시 폴더 빈 곳이 300MB 밑이면
  경고하고, 죽은 걸음에는 힌트를 붙인다. 임시 폴더를 메모리 쪽으로 돌리면 (`TMPDIR=/dev/shm/eng2p_tmp python3 scripts/all.py`) 디스크와 상관없이 돈다
- 이 문서가 닿은 깃발과 선은 `python3 scripts/par_run.py --selftest` (실행기 깸 시험 아홉 판) 와 `python3 scripts/all.py --plan` 이 지킨다
