# 기능 라벨. 점수와 함께 "어떤 말을 해냈는가"를 적는 자료

신뢰도: B 생성 (규칙은 사람이 정했고 낱말은 기준서와 지은 줄에서 온 것이다)

## 1. 결정

사용자가 정했다 (2026-10-12).

1. 줄과 연습에 기능 라벨이 있게 한다. 학습 피드백을 점수만이 아니라 **어떤 기능(can-do)을 해냈는가**로도 준다.
2. **점수를 대체하지 않는다. 점수와 함께 쓴다.** 차례 결과(`pass` `near` `miss`), 점수, 레벨 곡선 데이터는 그대로이고 이 문서의 것은 거기에 **더한 것**이다. 이 파일에는 점수가 없다 (점수는 기존 데이터가 담당한다).
3. 개인별 실력 값은 여전히 금지다 (`spec_amendments.md:586` "도구는 두 사람의 실력을 나타내는 값을 갖지 않는다"). 기능 목록은 **팀 단위**로만 쓴다 (6장).

## 3. 카드 600장

카드 600장 중 기능 라벨 있음 **200**장, 없음 **400**장 (전 105장 17.5%, 지금 33.3%).
근거별 역할 **105**, repair 낱말 **9**, 등록부 **22**, 제목 **64**.

**새 분류를 짓지 않았다.** 라벨은 어휘 셋 가운데 하나다.

| 어휘 | 원본 | 낱말 |
|---|---|---|
| standard10 | 기준서 4.4 | 요청 거절 제안 불동의 사과 불평 칭찬 설명 협상 잡담 |
| repair | 기준서 2.1 repair 트랙 내용 | 되묻기 자기수정 끊김 처리 이해 확인 명료화 요청 시간 벌기 대화 유지 |
| authored | `authored.json` 줄과 연습의 `function`, `outings.json` 미션의 `functions` | 줄 121종 / 미션 26종 (예 인사 확인 값 묻기) |

붙이는 규칙 (위에서부터. **카드 자신의 것이 있으면 강의 것은 안 쓴다**):

| 근거 `by` | 규칙 | 장 |
|---|---|---|
| `purpose` | 역할형 카드 A 면의 `purpose`. 역할형은 105장 전부 있다 | 105 |
| `pass` | repair형 카드의 `a.pass` 에 repair 낱말이 그대로 있다 ("되묻기로 대응하면 성공") | 9 |
| `rotation` | 그 카드가 든 강의가 `state/rotation.md` 3.1 조합 등록부에 있다 (기능 코드 F01~F10). 화용 강의 13편 전부 | 22 |
| `title` | 그 카드가 든 강의 **제목**에 어휘 셋의 낱말이 있다. 청크와 repair 트랙 강의에만 쓴다 (예 50강 "거절 덩어리" -> 거절, 42강 "이해 확인과 명료화 요청" -> 이해 확인, 명료화 요청) | 64 |

카드 -> 강의는 `lectures.json` 의 카드 구간(`cards.from/to`)이다. 낱말 찾기는 긴 낱말부터 겹치지 않게다. 기준서와 repair 낱말은 그대로 들어 있으면 되고, 지은 줄의 흔한 낱말(인사, 확인, 묻기...)은 앞뒤가 한글이 아닐 때만 인정한다.
검사기(`check_functions.py` force 판)가 억지 붙이기를 막는다: 소리, 자동화, 문법 트랙 강의에는 `rotation` `title` 이 붙으면 실패다. 화용 13편은 전부 등록부로 붙어 있어야 한다.

## 4. 결과 줄과 `pick`

`outing_turn` 에 선택 칸 `pick` (고른 후보 줄 id, `^[a-z]{2,4}-[0-9]{1,3}$`)이 더해졌다 (`game_results.md` 4.15 개정 3).
점수 차례 **213**개 중 기능이 갈리는 차례 **53**개 (나머지 160은 후보가 하나이거나 후보들의 기능이 같아서 `pick` 없이도 안다).

`pick` 으로 기능을 읽는 법 (키 이름은 점수와 같은 결과 줄에서 그대로 쓴다 -> 같은 행에서 함께 읽는다):

```
outing_turn {mission, turn, outcome, pick}
  기능 = functions.turns[mission][turn].pick[pick]        (pick 이 있으면)
       = functions.turns[mission][turn].same              (pick 이 없으면. null 이면 기능을 모른다)
card_run {id, outcome}
  기능 = functions.cards[id].fn
```

`outcome` 과 점수는 기존 그대로다. 이 자료는 기능만 더한다.

## 5. 하루 요약에 쓸 팀 단위 사실

두 줄이다. 점수, 느낌표, 사람 이름이 없다. 기능 낱말은 이미 있는 한국어 풀이 그대로다.

| 줄 | 만드는 법 |
|---|---|
| 오늘 해낸 말: <기능 목록> | 그날 `outing_turn` 중 `outcome` 이 `pass` 나 `near` 인 차례의 기능 (4장). 같은 기능은 한 번. 미션 단위로 쓰려면 끝난 미션의 `missions[id].functions`. 카드는 `card_run` 의 `pass` `near` 인 카드의 `cards[id].fn` |
| 다시 만날 자리: <같은 기능 다른 미션> | `byLineFunction[해낸 기능]` 에서 지금 미션을 빼고 `missions[id].unlock` 이 오늘 세션 이하인 것. 미션 단위는 `byMissionFunction`. 순서는 열리는 세션 순서다 |

`miss` 와 `skipped` 의 기능은 세지 않는다 (`tone.md` 3장 "못 한 것을 세는 칸을 아예 안 만든다. 한 것만 적는다"). "다시 만날 자리"도 해낸 기능에서만 나온다.
연습 말(`practice[]`)의 기능은 색인에 넣지 않았다 (틀 1, 틀 2 처럼 문형 이름이 섞여 있다). 게임이 필요하면 `authored.json` 을 직접 읽는다.

## 6. 사람이 확인할 점

> **사용자 확인 (2026-10-12): 아래 1·2·3 모두 확정했다.** 1 팀 단위 기능 목록은 괜찮다, 2 `near` 도 '해낸 말'에 넣는다, 3 강의 단위 라벨 86장의 가정(그 강의 카드 전부가 그 기능을 연습한다)을 받아들인다.

1. **팀 단위 통과 기능 목록은 "실력 값"이 아니라고 읽었다.** `spec_amendments.md:586` ("도구는 두 사람의 실력을 나타내는 값을 갖지 않는다")는 값, 점수, 수준을 막는다. 이 자료는 값이 아니라 그날 팀이 해낸 말의 이름이고, 사람별로 안 가르며(`seat` 를 안 쓴다), 낱말 수나 비율을 안 낸다. 그러나 이것은 **해석**이다. 사용자가 확인한다. 아니라고 하면 하루 요약의 두 줄은 빼고 자료만 남긴다.
2. `near` (다시 하거나 고치고서야 넘었다)를 "해낸 말"에 넣었다. 5.1 의 뜻이 "넘었다"이기 때문이다. 빼려면 4장 표를 `pass` 만으로 한다.
3. 강의 단위 라벨(`rotation` `title` 86장)은 "그 강의의 카드 전부가 그 기능을 연습한다"는 가정이다 (B). 판정형 카드가 덩어리의 자리를 가리는 것처럼 기능 자체를 말하지 않는 카드도 섞여 있을 수 있다. 사람이 강의 몇 편을 열어 보고 가정을 확인한다.
4. repair 카드 9장은 `a.pass` 문장에 "되묻기" 가 그대로 있는 경우만 붙였다. 나머지 repair형 카드는 문장에 낱말이 없어서 안 붙였다 (예 "되물으면" 처럼 활용형이면 낱말로 안 센다). 활용형까지 센 규칙으로 넓힐지는 사람이 정한다.
5. 칭찬 금지(`tone.md` 2장)와 사실 한 줄("오늘 해낸 말: ...")이 맞는지는 사람이 읽고 정한다 (H1 2.6 사람이 정할 것 2).
