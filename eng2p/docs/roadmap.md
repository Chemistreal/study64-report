검사는 매 턴 끝에 여섯 개를 돌린다. 하나라도 실패면 그 턴은 안 끝난 것이다.

```bash
python3 eng2p/scripts/check.py eng2p/out/

python3 eng2p/scripts/check_cards_plan.py
python3 eng2p/scripts/check_blocks.py

```

검사기가 늘어난 것은 매번 사람이 못 본 것을 하나씩 잡았기 때문이다.
check_media 는 조수가 화자 수를 낮춰 통과한 것을 잡았고,

검사기를 늘리는 쪽이 눈으로 다시 보는 쪽보다 언제나 싸다.

Q3는 개수를 통과 조건으로 잡는다. 그러면 일부러 만들어야 한다.

61강이 그것을 다룬다. 자동화 트랙에 넣은 이유가 있다.
LRE 는 막히는 자리에서 생기고 막히는 자리는 인출이 안 되는 자리다.
자동화 진단과 같은 자리를 다른 눈으로 보는 것이다.

**개수를 목표로 잡으면 형식적으로 채우게 된다.** 그 위험을 61강에 적는다.
해결한 LRE 와 미해결 LRE 를 갈라 세고 미해결이 절반을 넘으면 8회를 못 채운 것으로 본다.

### 11.1 왜 100턴을 더 쓰는가

강의 96편을 다 쓴 자리에서 사용자가 편의성이 떨어진다고 했다. 확인해 보니 맞다.
**지금 산출물은 마크다운 파일 더미이고 그것은 대화 세션이 주는 것과 같은 형태다.**

앱을 열어 확인한 것이다.

| 자리 | 지금 | 문제 |
|---|---|---|
| 학습자가 펴 놓을 것 | 없다 | 강의 파일은 제작 설계서다. 블록 3과 4가 제작 지시라 세션 중에 못 쓴다 |
| 앱이 아는 자료 | 없다 | renderDocs 가 GitHub 링크만 던진다. 96편도 600장도 288개도 앱 밖이다 |
| 복습 탭 | LRE 만 돈다 | 커리큘럼 카드 600장을 앱이 모른다 |
| 첫 페이지 | 입력 폼이다 | 오늘 몇 강인지 어느 카드인지가 화면에 없다 |
| 영상 | 라이브러리 탭에만 있다 | 세션 흐름에 안 붙어 있고 구간 반복이 안 된다 |
| B등급 | 96건 전부 보류 | 확인 안 된 그럴듯함 |

### 11.2 영상에 대해 먼저 확인한 사실

계획을 짜기 전에 재 봤다. 짐작으로 계획을 세우면 그 계획이 틀린다.

| 확인 | 값 |
|---|---|
| 앱이 이미 영상을 재생하는가 | **한다.** renderLibPlay 가 `video` 요소를 만들어 catalog 의 video 를 건다 |
| 어디서만 되는가 | 미디어 탭 하나. 세션 블록에 안 붙어 있다 |
| 원격 재생이 되는가 | 된다. `access-control-allow-origin: *` 이고 range 요청을 받는다 |
| 영상을 저장소에 넣을 수 있는가 | **못 넣는다.** 1과 15.7MB, 21과 19.2MB, 45과 24.6MB다 |
| 52개면 | 1GB 를 넘는다. 저장소가 지금 164MB 이고 GitHub Pages 한도에 걸린다 |
| 소리는 | 52개 53MB 가 이미 로컬에 있다 |

그래서 방향이 정해진다.

**영상 파일은 안 받아 온다. 원격 주소를 앱 안에서 재생한다.**
링크로 새 창을 여는 것이 아니라 세션 화면 안에서 돈다. 그 차이가 사용자가 말한 것이다.
range 를 받으므로 구간 반복과 배속도 원격 파일에서 된다.

**그리고 소리는 망 없이 되고 영상은 망이 있어야 한다.**
세션 설계가 이 사실을 알아야 한다. 블록 1 소리 입력은 mp3 로 돌리고
영상은 블록 4 공동 입력에만 건다. 망이 끊기면 영상 자리가 소리로 내려간다.

## 12. 3차 로드맵. T158 ~ T257 (100턴). 놀이와 2인

신뢰도: A 생성 (제작 관리 계획)

### 12.1 왜 또 백 턴인가

2차까지 물은 것은 **"맞는가"** 였다. 자료가 근거를 대는가, 파생물이 원본과 같은가,
인용이 그 줄을 가리키는가. 그것은 다 끝났고 검사기 서른두 걸음이 지킨다.

3차가 묻는 것은 **"내일 또 여는가"** 다.

기준서 1장이 최우선 기준을 완주 생존률로 잡았다. 그런데 완주는 정확한 자료로 하는 것이
아니다. **480회를 여는 것으로 한다.** 지금 앱은 480회를 정확하게 안내하지만
열고 싶게 만드는 장치가 하나도 없다. 2차 로드맵 D구간에서 마찰을 줄였을 뿐이다.
마찰을 줄이는 것과 끌어당기는 것은 다른 일이다.

그리고 하나 더 있다. **지금 앱은 두 사람이 쓰는 앱이 아니라 한 사람이 두 번 쓰는 앱이다.**
역할을 글자로 알려 줄 뿐 화면이 갈리지 않는다. 두 사람이 같은 방에 있다는 조건을
쓰는 자리가 없다. 그 조건이 이 과정의 제일 큰 자산인데 앱이 그것을 안 쓴다.

### 12.2 견준 것과 무엇을 뜯었는가

여섯 앱을 장치 단위로 뜯었다. 기능 목록이 아니라 **무엇이 사람을 돌아오게 하는가**로 봤다.

| 앱 | 붙잡는 장치 | 도는 원리 |
|---|---|---|
| Duolingo | 연속일, 일일 목표, 리그, 하트, 친구 퀘스트 | 끊기는 것이 아까워서 돌아온다. 손실 회피다 |
| Anki | 간격 반복, 오늘 할 장 수 | 오늘 안 하면 내일 두 배다. 밀리는 것이 벌이다 |
| Pimsleur | 하루 한 과 30분 고정, 못 넘어가면 그 과 반복 | 고를 것이 없다. 결정 피로를 없앤다 |
| Memrise | 원어민 짧은 영상, 상황별 묶음 | 진짜 사람이 말하는 것을 본다 |
| Busuu | 원어민 첨삭 주고받기 | 남이 내 것을 본다는 사실 |
| Drops | 5분에 잘린다. 더 하고 싶어도 못 한다 | 모자란 채로 끝낸다 |

**여섯이 다 1인용이다.** 사회성은 경쟁(리그)이거나 비동기(친구 알림)다.
같은 방에 두 사람이 마주 앉은 조건을 쓰는 장치가 **하나도 없다.**
그래서 붙잡는 장치는 이쪽에서 가져오되 **놀이의 뼈대는 다른 데서 가져온다.**

같은 방에서 둘이 하는 놀이의 구조를 여섯 개 뜯었다. 이름이 아니라 구조를 본다.

| 구조 | 어떻게 도는가 | 우리 자리 |
|---|---|---|
| 정보 격차 | 한쪽만 답을 안다. 그래서 말이 필요해진다 | 화용, repair |
| 단서 주기 | 낼 사람이 더 어렵다. 출제가 곧 훈련이다 | 청크, 자동화 |
| 시간 압박 | 생각할 틈을 없애 자동화된 것만 나오게 한다 | 자동화, repair |
| 틀린 데 찾기 | 듣는 쪽이 능동이 된다 | 소리 |
| 이어 붙이기 | 둘이 하나를 만든다. 끊기면 같이 끊긴다 | 청크 |
| 뒤집힌 판정 | 채점하는 쪽이 기준을 배운다 | 문법, 화용 |

**정보 격차가 핵심 구조다.** 그것 하나만으로 "말하기 연습"이 "말할 이유"로 바뀐다.
그런데 정보 격차는 화면이 갈려야 성립한다. 그래서 K구간(기기 둘)이 L구간(놀이)보다 앞에 온다.
순서를 뒤집으면 놀이를 만들어 놓고 돌릴 자리가 없다.

### 12.4 2인 놀이 원칙 다섯

놀이를 만들기 전에 헌법을 먼저 박는다. **이 다섯을 어기는 놀이는 안 만든다.**

1. **점수는 공동으로만 쌓인다.** 화면 어디에도 개인 칸이 없다
2. **이기는 쪽은 둘이거나 없다.** 상대를 이기는 판은 안 만든다
3. **못 하는 쪽이 정보를 쥔다.** 뒤처진 쪽이 출제자가 되는 자리를 반드시 둔다
4. **침묵이 지는 것이 되는 판은 안 만든다.** 시간 압박은 공동 계수에만 건다
5. **역할은 판마다 바뀐다.** 한 판 안에서도 바뀐다

3번이 이 다섯 중 제일 중요하다. 부부의 실력 격차는 반드시 생긴다.
격차 자체는 위험이 아니지만 **잘하는 쪽이 늘 가르치는 자리에 서면** 그것이 2.4의 고착이다.
출제자는 답을 쥔다. 답을 쥔 쪽이 그 판의 강자다. 그 자리를 번갈아 준다.

### 12.14 이 로드맵에서 늘어나는 검사기

놀이는 사람이 판정한다. 그러면 기계는 무엇을 보는가. 이것이 T166 의 물음이고
답을 못 내면 L구간 스무 턴이 검사 밖에 있게 된다.

| 검사기 | 무엇을 보는가 |
|---|---|
| `check_play.py` | 판마다 시작 조건과 끝 조건과 판정 주체가 적혀 있는가. 12장 전수 |
| `check_play_solo.py` | **1인으로 돌아가는 판이 있는가.** 있으면 13.2 위반이다 |
| `check_play_score.py` | 개인 칸이 코드와 화면에 없는가. 원칙 1과 4의 기계 판정 |
| `check_pair.py` | 두 기기 상태가 갈라졌다 합쳐질 때 값이 안 깨지는가 |
| `check_streak.py` | 공동 연속일이 한 사람만으로 이어지지 않는가 |
| `check_play_ui.js` | 열두 판 전수 자동 진행. 화면 검사기 안 |

**`check_play_score.py` 가 이 로드맵의 핵심 게이트다.** 개인 점수를 안 만들겠다는 것은
말로 하면 지켜지지 않는다. G구간에서 배웠다. 적어 둔 것은 검사가 아니다.
