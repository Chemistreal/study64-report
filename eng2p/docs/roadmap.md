검사는 매 턴 끝에 여섯 개를 돌린다. 하나라도 실패면 그 턴은 안 끝난 것이다.

```bash
python3 eng2p/scripts/check.py eng2p/out/

python3 eng2p/scripts/check_cards_plan.py
python3 eng2p/scripts/check_blocks.py

```

검사기가 늘어난 것은 매번 사람이 못 본 것을 하나씩 잡았기 때문이다.
check_media 는 조수가 화자 수를 낮춰 통과한 것을 잡았고,

검사기를 늘리는 쪽이 눈으로 다시 보는 쪽보다 언제나 싸다.

Q3는 개수를 통과 조건으로 잡는다. 그러면 일부러 만들어야 한다.

61강이 그것을 다룬다. 자동화 트랙에 넣은 이유가 있다.
LRE 는 막히는 자리에서 생기고 막히는 자리는 인출이 안 되는 자리다.
자동화 진단과 같은 자리를 다른 눈으로 보는 것이다.

**개수를 목표로 잡으면 형식적으로 채우게 된다.** 그 위험을 61강에 적는다.
해결한 LRE 와 미해결 LRE 를 갈라 세고 미해결이 절반을 넘으면 8회를 못 채운 것으로 본다.

### 11.1 왜 100턴을 더 쓰는가

강의 96편을 다 쓴 자리에서 사용자가 편의성이 떨어진다고 했다. 확인해 보니 맞다.
**지금 산출물은 마크다운 파일 더미이고 그것은 대화 세션이 주는 것과 같은 형태다.**

앱을 열어 확인한 것이다.

| 자리 | 지금 | 문제 |
|---|---|---|
| 학습자가 펴 놓을 것 | 없다 | 강의 파일은 제작 설계서다. 블록 3과 4가 제작 지시라 세션 중에 못 쓴다 |
| 앱이 아는 자료 | 없다 | renderDocs 가 GitHub 링크만 던진다. 96편도 600장도 288개도 앱 밖이다 |
| 복습 탭 | LRE 만 돈다 | 커리큘럼 카드 600장을 앱이 모른다 |
| 첫 페이지 | 입력 폼이다 | 오늘 몇 강인지 어느 카드인지가 화면에 없다 |
| 영상 | 라이브러리 탭에만 있다 | 세션 흐름에 안 붙어 있고 구간 반복이 안 된다 |
| B등급 | 96건 전부 보류 | 확인 안 된 그럴듯함 |

### 11.2 영상에 대해 먼저 확인한 사실

계획을 짜기 전에 재 봤다. 짐작으로 계획을 세우면 그 계획이 틀린다.

| 확인 | 값 |
|---|---|
| 앱이 이미 영상을 재생하는가 | **한다.** renderLibPlay 가 `video` 요소를 만들어 catalog 의 video 를 건다 |
| 어디서만 되는가 | 미디어 탭 하나. 세션 블록에 안 붙어 있다 |
| 원격 재생이 되는가 | 된다. `access-control-allow-origin: *` 이고 range 요청을 받는다 |
| 영상을 저장소에 넣을 수 있는가 | **못 넣는다.** 1과 15.7MB, 21과 19.2MB, 45과 24.6MB다 |
| 52개면 | 1GB 를 넘는다. 저장소가 지금 164MB 이고 GitHub Pages 한도에 걸린다 |
| 소리는 | 52개 53MB 가 이미 로컬에 있다 |

그래서 방향이 정해진다.

**영상 파일은 안 받아 온다. 원격 주소를 앱 안에서 재생한다.**
링크로 새 창을 여는 것이 아니라 세션 화면 안에서 돈다. 그 차이가 사용자가 말한 것이다.
range 를 받으므로 구간 반복과 배속도 원격 파일에서 된다.

**그리고 소리는 망 없이 되고 영상은 망이 있어야 한다.**
세션 설계가 이 사실을 알아야 한다. 블록 1 소리 입력은 mp3 로 돌리고
영상은 블록 4 공동 입력에만 건다. 망이 끊기면 영상 자리가 소리로 내려간다.

## 12. 3차 로드맵. T158 ~ T497 (340턴). 손맛과 놀이

신뢰도: A 생성 (제작 관리 계획)

### 12.1 왜 340턴인가

앞서 백 턴으로 잘랐던 판을 사용자가 턴 제한 없이 다시 짜라고 했다.
백 턴 판에서 잘라낸 것이 뭐였는지부터 적는다. **잘린 것이 곧 늘어난 것이다.**

| 백 턴 판에서 잘린 것 | 왜 잘렸었나 | 이제 어디 |
|---|---|---|
| 앱 여섯만 뜯음 | 턴이 없어서 | B단계. 서른둘을 뜯는다 |
| 놀이 열두 판 | 판당 1.7턴 | E단계. 스무 판, 판당 세 턴 |
| 세션 러너 손질 없음 | 통째로 빠졌다 | C단계 스물다섯 턴 |
| 소리 판정 없음 | 못 한다고 봤다 | H단계. 파형으로 박자를 잰다 |
| 적응 없음 | 빠졌다 | G단계. 둘의 진도가 갈릴 때 |
| 자료 확장 없음 | 있는 것만 쓰기로 | J단계 서른 턴 |
| 2년차 없음 | 1년만 봄 | L단계 열다섯 턴 |
| 리허설 12일 | 짧다 | M단계. 4주 |

**턴 하나는 실패할 수 있는 산출 하나다.** 검사기가 판정할 수 없는 것은 턴으로 안 센다.
그 잣대로 세어 340이 나왔다. 늘리려고 쪼갠 자리는 없다.

### 12.2 언제 멈춰도 되는가

340턴은 한 번에 다 도는 계획이 아니다. **단계마다 끝이 배포 가능한 지점이다.**

| 여기서 멈추면 | 손에 남는 것 |
|---|---|
| A단계 끝 (T187) | 지금 앱이 훨씬 빠르고 손에 붙는다. 놀이는 없다 |
| D단계 끝 (T257) | 기기 둘이 갈린다. 2인 앱이 된다. 놀이는 아직 |
| E단계 끝 (T317) | **놀이 스무 판이 다 돈다. 여기가 제일 큰 분기점이다** |
| F단계 끝 (T342) | 공동 연속일과 퀘스트. 붙잡는 장치가 완성된다 |
| I단계 끝 (T397) | 상용 앱과 견줄 만한 완성도 |
| N단계 끝 (T497) | 2년차까지 넘길 수 있는 상태 |

**A와 E와 F 셋만 해도 이 앱은 다른 물건이 된다.** 나머지는 그 위에 쌓는 것이다.

### 12.3 순서. 손에 잡히는 것이 먼저다

처음 짠 판은 뜯어보기로 시작했다. 그것을 뒤로 뺐고 이번에도 뒤에 둔다.

놀이는 아직 없지만 첫 화면과 조작은 지금 매일 쓰고 있다.
**쓰고 있는 것의 결함이 없는 것의 부재보다 급하다.**
그리고 뜯어보기가 끝나도 화면에 바뀌는 것이 없다. 계획의 첫머리가
아무것도 안 바꾸면 그 계획은 시작부터 밀린다.

이 순서에는 값이 붙는다. **첫 화면을 두 번 손대게 된다.**
놀이와 공동 연속일이 나중에 올라오기 때문이다. 알고도 이렇게 짰다.
대신 T166 에서 빈 자리를 미리 잡는다. 무엇이 들어올지는 12.9 와 12.16 에
이미 적혀 있으니 자리 크기는 지금 정할 수 있다. 두 번째 손질을 다시 짜는 일이
아니라 채우는 일로 만든다.

#### 12.5.4 같은 방 놀이 여덟

언어 앱 열넷이 다 1인용이다. 사회성이라고 부르는 것이 경쟁(리그)이거나
비동기(친구 알림)다. **같은 방에 두 사람이 마주 앉은 조건을 쓰는 앱이 없다.**
그래서 놀이의 뼈대는 여기서 가져온다. 이름이 아니라 구조를 본다.

| 구조 | 어떻게 도는가 | 우리 자리 |
|---|---|---|
| 정보 격차 | 한쪽만 답을 안다. 그래서 말이 필요해진다 | 화용, repair |
| 협력형 정보 격차 | **내 것은 내가 못 보고 상대만 본다** | 소리. 자기 발음은 자기가 못 듣는다 |
| 눈금 맞추기 | 한쪽이 눈금 위 한 점을 보고 그 정도로 말한다 | 화용. 격식의 세기 |
| 단서 겹침 지우기 | 둘이 낸 단서가 같으면 지운다 | 어휘 넓히기 |

| 시간 압박 | 생각할 틈을 없애 자동화된 것만 나오게 한다 | 자동화, repair |

| 뒤집힌 판정 | 채점하는 쪽이 기준을 배운다 | 문법, 화용 |

**협력형 정보 격차가 이번에 새로 들어온 구조다.** 백 턴 판에는 없었다.
자기 발음은 자기가 못 듣는다. 상대만 듣는다. 그 비대칭이 놀이의 뼈대가 된다.
벌을 안 주면서 서로 고쳐 주게 만드는 유일한 구조다.

### 12.8 2인 놀이 원칙 여섯

놀이를 만들기 전에 헌법을 박는다. **이 여섯을 어기는 놀이는 안 만든다.**

**확정판은 `docs/play.md` 다 (T201).** 근거 조항과 부딪치는 자리 넷과
원칙마다 무엇이 검사하는지가 거기 있다. 요구사항 P1~P3 도 거기서 나왔다.

1. **점수는 공동으로만 쌓인다.** 화면 어디에도 개인 칸이 없다
2. **이기는 쪽은 둘이거나 없다.** 상대를 이기는 판은 안 만든다
3. **못 하는 쪽이 정보를 쥔다.** 뒤처진 쪽이 출제자가 되는 자리를 반드시 둔다
4. **침묵이 지는 것이 되는 판은 안 만든다.** 시간 압박은 공동 계수에만 건다
5. **역할은 판마다 바뀐다.** 한 판 안에서도 바뀐다
6. **한 판은 5분을 안 넘는다.** 넘으면 그것은 놀이가 아니라 블록이다

3번이 제일 중요하다. 부부의 실력 격차는 반드시 생긴다. 격차 자체는 위험이 아니다.
**잘하는 쪽이 늘 가르치는 자리에 서면** 그것이 2.4의 고착이다.
출제자는 답을 쥔다. 답을 쥔 쪽이 그 판의 강자다. 그 자리를 번갈아 준다.

### 12.24 늘어나는 검사기

놀이는 사람이 판정한다. 그러면 기계는 무엇을 보는가.
답을 못 내면 E단계 예순 턴이 검사 밖에 있게 된다.

| 검사기 | 무엇을 보는가 | 단계 |
|---|---|---|
| `check_friction.js` | 누름과 화면 부피 일곱 줄. **friction.md 기준선보다 늘면 실패** | A |
| `check_theme.py` | 색 토큰이 한 벌인가. 두 벌이 안 돌아왔는가 | A |
| `check_session.py` | 블록 넷이 다 화면을 갖는가. 회차 셋이 다른가 | C |
| `check_pair.py` | 두 기기 상태가 갈라졌다 합쳐질 때 값이 안 깨지는가 | D |
| `check_play.py` | 판마다 시작 끝 판정 주체가 적혀 있는가. 스무 판 전수 | E |
| `check_play_solo.py` | **1인으로 돌아가는 판이 있는가.** 있으면 13.2 위반 | E |
| `check_play_ui.js` | 스무 판 전수 자동 진행 | E |
| `check_play_score.py` | 개인 칸이 코드와 화면에 없는가 | F |
| `check_streak.py` | 공동 연속일이 한 사람만으로 이어지지 않는가 | F |
| `check_daily_cap.py` | 오늘의 한 판이 하루 두 번 열리지 않는가 | F |
| `check_adapt.py` | 트랙별 사람별 진도가 어긋나도 안 깨지는가 | G |
| `check_sound_judge.py` | 기계 판정이 통과 근거로 쓰이지 않는가 | H |
| `check_tone.py` | 다그치는 말투가 화면에 없는가 | I |

| `check_export.py` | 내보낸 것을 들여오면 같은 상태가 되는가 | K |

**게이트 셋이 이 로드맵의 중심이다.**

`check_friction.js` 와 `check_perf.py` 는 **고친 것이 다시 나빠지는 것**을 막는다.
편의성과 속도는 화면에 뭘 더할 때마다 한 번씩 나빠진다. 숫자로 박아 두는 수밖에 없다.

`check_play_score.py` 는 **원칙이 지켜지는지**를 본다. 개인 점수를 안 만들겠다는
것은 말로 하면 안 지켜진다. G구간에서 배웠다. **적어 둔 것은 검사가 아니다.**
