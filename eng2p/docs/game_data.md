# 게임 자료 계약. 판정 열쇠, NPC 응답, 목소리 목록, 덱 이름

상위 규격: docs/game.md / docs/scenes.md / docs/improve.md 5장 (U6, U7)
작성일: 2026-10-08

게임은 `out/game/sessions.json` 과 `scenes.json` 과 `town.json` 을 받아 그린다 (game.md 1장).
그런데 **말을 듣고 채점하고 NPC 가 말하려면 그 셋에 없는 자료가 더 필요했다.**
언리얼 설계 감사가 빈자리를 넷 짚었다. 정답을 기계가 읽는 꼴로, 역할형 카드에서 NPC 가 할 말, NPC 소리 일감, 덱에 섞인 라디오 인물 이름이다.

## 3. 판정 열쇠 (judge.json)

판정형 카드의 `a.answer` 는 사람이 읽는 글이다.
"1) Pete  2) Anna" 도 있고 "다섯 개 모두 1음절이다" 도 있고 "읽은 쪽을 A면 아래 빈칸에 표시해 두고" 도 있다.
`judge.json` 은 그 글을 **게임이 읽는 꼴**로 옮긴다. 통과선은 `a.pass` 의 숫자에서, 열쇠는 `a.answer` 에서 읽는다.
읽는 길이 셋이다. 번호 목록과 갈래 목록은 글에서 바로 읽는다. 한 줄 산문은 몇 꼴만 정규식으로 읽고 나머지는 3.1 표가 읽은 값을 준다. 3.1 표의 근거 문구가 카드 글에 그대로 있어야 한다.

### 3.2 열쇠 없는 카드

낱말이나 이름표로 채점할 수 없는 카드가 넷이다. 이 표가 **정확한 목록**이다. 하나 늘거나 줄면 검사가 실패한다.
규칙 이름은 게임이 어떤 관찰로 채점하는지 가리킨다. 처음부터 다시 시작했는가, 한국어 소리가 났는가, 두 사람이 센 값이 같은가다. 값이 아니라 행동이나 일치를 본다.

|---|---|---|---|
| Q1-136 | behavior | restart_detect | 답이 낱말이 아니라 행동이다. 처음부터 다시 시작하면 실패이고 고친 자리부터 이어 가면 성공이다 |
| Q1-145 | behavior | korean_detect | 답이 낱말이 아니라 소리의 갈래다. 한국어 소리가 나오면 그 항목은 실패이고 영어 소리로 자리를 잡으면 성공이다 |

### 3.3 열쇠의 형태

`key.form` 은 여덟 가지다. 칸(`items`) 수는 재료(`a.material`) 수와 같다. 예외는 읽는 쪽이 고르는 카드(`plan`)와 열쇠 없는 카드다.

| 형태 | 칸 하나의 값 | 게임이 하는 일 | 장 |
|---|---|---|---|
| tokens | `{of: [낱말들], need: k}` | 말하거나 짚은 것 가운데 낱말이 k 개 이상 들리면 그 칸이 맞다. `match` 가 word 면 낱말, phrase 면 이어진 덩어리다. `gap` 이 참이면 가운데는 바뀌는 자리다 | 29 |
| number | 정수 | 손가락으로 낸 수와 같으면 맞다. `pair` 가 참이면 앞뒤 둘이다 | 19 |
| label | 이름표 하나나 `multi` 면 이름표들 | 고른 칩이 같으면 맞다. 선택지는 `labels` 다 | 58 |
| side | 0 이나 1 | 두 보기 가운데 고른 쪽이 같으면 맞다. 보기는 `options` 다 | 11 |
| flag | 참이나 거짓 | 그렇다 아니다를 고른다. 이름은 `flagLabel` 이다 | 12 |
| position | 낱말 안의 글자 자리 | 끼운 소리의 자리를 짚는다 | 1 |
| npc_pick | 칸 없음. `plan` | 3.5 | 6 |
| open | 칸 없음 | 3.2 표의 규칙으로 채점한다 | 4 |

위 장은 2026-10-08 판의 카드 수다. 최신 값은 `judge.json` 이 가진다.

이름표 목록(`labels`, `options`)은 선택지라서 칩으로 그려도 된다. **숨기는 것은 칸마다 무엇이 맞는지(`items`)뿐이다.**
이름표는 카드 답에 적힌 낱말 그대로다. 34장은 B 면 지시가 부르는 이름과 달라서(Q3-008 의 1층은 지시에 없다) 칩 글은 `labels` 에서 만든다. 지시의 이름으로 바꾸는 일은 카드 러너 단계가 정한다.

### 3.4 답하는 길

`input` 은 두 사람이 답하는 길이다. B 면 지시의 동사에서 읽되 이름표 열쇠는 늘 칩으로 받는다.
한국어 이름표(격식, 시작, 1형 ...)는 영어 받아쓰기 모델이 못 받아서 **말로 받지 않는다** (game.md 6장).

| 길 | 뜻 | 카드 수 |
|---|---|---|
| choose | 칩이나 보기를 누른다 | 86 |
| speak | 영어로 말한다 | 23 |
| count | 손가락으로 낸 수를 누른다 | 19 |
| tap_word | 문장 안의 낱말을 짚는다 | 5 |
| observe | 채점 규칙이 소리나 행동을 본다 (3.2 표) | 4 |
| tap_position | 낱말 안의 글자 사이를 짚는다 | 1 |
| write | 낱말을 적는다 | 1 |

### 3.5 읽는 쪽이 고르는 카드

여섯 장은 A 가 어느 쪽을 읽을지가 답이다 (한쪽만 읽기, 두 개만 고르기, 같은 덩어리를 흘려 읽기, 강세를 넣는 자리). 사람이 정하던 것을 NPC 가 정해야 한다.
**게임에 난수를 안 쓰고 C++ 에 고르는 코드를 안 둔다** (audit U1). 그래서 `plan` 이 데이터에 있다.
`plan[i]` 는 카드 번호와 칸 번호의 sha1 순서로 정한 0 이나 1 이다. 앞쪽 절반이 1 이고 어느 쪽이 더 많은지는 카드 번호 해시가 정한다. 두 기기가 같다.
`pick: order` 에서 1 은 흘린 쪽이 두 번째라는 뜻이다. `two_of_all` 은 읽을 두 칸 번호다.

### 3.6 통과선

`k` 와 `n` 은 `a.pass` 에서 읽는다. "5개 중 4개 이상" 은 4 와 5, "5개 모두" 와 "두 개를 다" 는 n 과 n 이다.
B 면에 적힌 통과선이 다르면 `kShown` 에 같이 적는다. 세 장이다 (Q1-009 A 5 B 4, Q1-021 과 Q1-044 A 2 B 1).
**게임은 `k` 로 채점하고 B 면 글은 그대로 보인다.** 둘 중 어느 쪽을 쓸지는 카드를 고친 사람이 정할 일이라 여기서 안 고른다.
제한 시간(`seconds`)이 있는 카드는 그 값을 같이 싣는다.

## 4. 역할형 카드의 NPC 응답 (replies.json)

역할형 카드에서 NPC 는 A 면을 맡는다 (game.md 5.1). 카드에는 상황, 관계, 목적, 격식, 끝 조건이 있다.
**NPC 가 무슨 영어를 말하는지는 어디에도 없었다.** 지어 말하면 1번 규칙을 깬다.
그래서 줄은 이미 들은 대본에서만 고른다. 줄이 한 사람의 한 마디 안에서 이어진 문장 그대로여야 하고 그 과를 카드가 처음 나오는 세션까지 들었어야 한다.
`elements` 에 다섯 요소가 다 있는지, A 면과 B 면이 같은지, 관계와 목적과 격식이 정해진 낱말 안인지를 적고 검사가 본다.

### 4.1 응답 함수와 후보 줄

후보는 격식마다 순서가 다르다. 처음 들은 것으로 닿는 첫 줄을 쓴다. 이름 자리가 있는 줄은 후보가 못 된다. NPC 는 누구든 말할 수 있어야 한다.

### 4.2 목적에서 함수로

끝 조건을 줄 하나로 닫을 수 있으면 닫는 함수의 줄을 쓰고 (4.3 표의 셋째 칸이 예), 아니면 첫 반응 함수의 줄을 쓴다.

| 목적 | 첫 반응 | 닫는 함수 | 까닭 |
|---|---|---|---|
| 요청 | grant | grant | B 가 부탁하면 NPC 는 들어준다 |
| 제안 | approve | approve | B 가 제안하면 NPC 는 받는다 |
| 불평 | sympathize | agree | B 가 불평하면 NPC 는 안됐다고 하고 정해지면 받아 닫는다 |
| 사과 | take_apology | take_apology | B 가 사과하면 NPC 는 받아 준다 |
| 칭찬 | thanks | thanks | B 가 칭찬하면 NPC 는 고맙다고 한다 |
| 거절 | accept_refusal | accept_refusal | B 가 거절하면 NPC 는 물러난다 |
| 불동의 | acknowledge | agree | B 가 다르다고 하면 NPC 는 알았다고 하고 정해지면 받아 닫는다. 버티는 첫 반응은 몸짓이다 |
| 설명 | acknowledge | agree | B 가 설명하면 NPC 는 듣고 알았다고 한다 |
| 협상 | agree | agree | 정해지면 NPC 는 받아 닫는다. 서로 다른 것을 원하는 첫 반응은 몸짓이다 |
| 잡담 | acknowledge | agree | B 가 말하면 NPC 는 맞장구를 친다 |

### 4.3 끝 조건 갈래

끝 조건 글에 낱말이 하나라도 있으면 그 갈래다. 위에서부터 본다. 한 줄로 못 닫는 갈래가 둘이다.
count 는 횟수나 시간으로 닫혀서 줄이 아니라 몸짓과 시계가 맡는다. content 는 NPC 가 새 말을 해야 닫혀서 줄은 첫 반응이고 나머지는 몸짓이다.

| 갈래 | 낱말 | 한 줄로 닫히나 | 뜻 |
|---|---|---|---|
| count | 세 번씩, 세 문장씩, 90초, 차례가 오면, 한 바퀴, 세 단계, 두 단계, 닫기까지, 다 밟으면, 다 지나면, 닫는 신호 | 횟수 | 횟수나 시간으로 닫힌다. 몸짓과 시계가 맡는다 |
| content | 말하면, 말하기 시작하면, 되풀이하면, 일러 주면, 알려 주면, 골라 주면, 알아들으면, 듣거나, 이야기가 나오면, 다 나오면, 묻고, 찾겠다고 | 아니오 | NPC 가 새 말을 해야 닫힌다 |
| settle | 정해지면, 잡히면, 기로 하면, 정하면, 확인되면 | 예 | 둘이 정하면 닫힌다. NPC 가 받아 닫는다 |
| answer | 답하면, 못 할지, 못 옮길지, 못 준다고 하면 | 예 | NPC 가 한 번 답하면 닫힌다 |
| accept | 받아 주면, 괜찮다고 하면, 물러나면 | 예 | NPC 가 받거나 물러나면 닫힌다 |

### 4.4 repair 카드 가운데 줄을 주는 것

repair 형 95장은 대부분 읽기 연습이거나 말없이 보는 카드다. A 면 지시가 NPC 에게 대화 반응 한 줄을 시키는 카드만 줄을 준다.

| 카드 | 함수 | 근거 문구 | 까닭 |
|---|---|---|---|
| Q3-012 | thanks | 고맙다고 말하고 | A 면 지시가 NPC 에게 고맙다고 말하라고 한다 |

### 4.5 게임이 쓰는 법

| 칸 | 뜻 |
|---|---|
| `reply.say` | NPC 가 말한다. 두 사람이 목적을 이룬 말을 하고 나서다 |
| `reply.completes` | 참이면 이 줄로 카드가 닫힌다. 거짓이면 줄은 첫 반응이고 `gesture` 와 이어서 두 사람이 마저 한다 |
| `reply` 가 null | NPC 는 몸짓만 한다. `reason` 이 까닭이다 (횟수나 시간으로 닫히는 카드) |
| `gesture` | 인물표에서 쓸 수 있는 몸짓이다. 전투와 쓰러짐 아홉은 안 쓴다 |
| `retry` | 못 알아들었을 때 하는 줄 "Let's try that again." (1과). 모든 카드에 쓴다 |

2026-10-08 판은 역할형 105장 가운데 줄이 있는 카드가 92장이다. 그중 59장은 줄 하나로 끝 조건이 닫히고 33장은 첫 반응만이다. 13장은 몸짓만이다.
repair 형은 한 장(Q3-012)에 줄이 있다.

**기계가 안 보는 것: 그 줄이 그 순간에 자연스러운가.** 목적을 반응 갈래로 보는 것은 B등급이다. 4주 리허설에서 두 사람 귀로 확인한다.

## 5. NPC 목소리 목록 (voicelist.json)

NPC 목소리는 TTS 이고 1층 전용이다 (game.md 2장). 소유자 PC 가 줄마다 미리 렌더한다 (game.md 8장 6번).
`out/game/voicelist.json` 이 그 일감이다. 줄마다 id, 인물, 글, 근거 대본, 목소리, 빠르기가 있다.

| 칸 | 뜻 |
|---|---|
| `id` | `v` 와 sha1(인물, 줄바꿈, 줄)의 앞 12자. 같은 인물이 같은 줄이면 같다 |
| `render` | `pre` 는 지금 렌더한다. `runtime` 은 이름 자리가 든 줄이라 두 사람이 이름을 정한 뒤 PC 에서 렌더한다 |
| `slots` | `{A}` `{B}` 이름, `{A철자}` `{B철자}` 이름을 글자마다 끊어 부른 것, `{A틀린철자}` `{B틀린철자}` 글자 하나를 빼거나 겹친 것 |
| `quarters` `speed` `pauseMs` | 그 줄이 나오는 분기와 분기마다의 빠르기와 문장 사이 쉼. 분기마다 빠르기가 달라 따로 렌더한다 |
| `from` `alsoFrom` | 근거 대본. 같은 줄이 대본 둘에 있으면 먼저 들은 과가 `from` 이다 |
| `kinds` | `scene` 장면, `reply` 카드 응답, `retry` 되묻는 줄 |
| `synthetic` `audioGrade` | 모든 줄이 참과 `C-gen` 이다. 실제 사람 녹음(라디오)은 이 목록에 없다 |
| `uncast` | 인물표에 없는 손님이라 목소리를 빌린 줄 |

소리 파일 이름은 `<id>.<분기>.wav` 다. 파일은 저장소에 안 넣는다 (CLAUDE.md).
카드 응답은 카드를 내는 NPC 가 읽는다 (town.md 5.3). 되묻는 줄은 장면이나 카드에 서는 인물마다 한 줄씩 있다.

## 6. 덱의 라디오 인물 이름 (deck_names.json)

판 덱의 글은 52과 대본 줄에서 왔다. 그래서 **라디오 인물 이름이 그대로 든 항목**이 있다. reask, cutin, clash, twohalf, swapline 이 그렇다.
NPC 가 그 줄을 읽으면 "I'm Anna." 가 NPC 의 말이 된다. 라디오 인물과 동네 사람은 섞지 않는다 (world.md 4장).
`out/game/deck_names.json` 이 이름 든 항목마다 처리를 하나 적는다. 라디오 인물 이름은 대본 52편 화자 칸에서 모은다.
항목 id 는 `d` 와 sha1(판, 칸, 글)의 앞 열 자다. 카드 번호로 부르는 판은 `card:카드번호#재료번호` 다. 게임은 읽기 전에 이 id 로 처리를 찾는다.

### 6.1 처리 둘

| 처리 | 언제 | 게임이 하는 일 |
|---|---|---|
| swap | 이름이 그냥 부르는 말이고 이름 자리({A} {B})로 바꾼 글이 그날 대본에서 이어진 문장 그대로일 때 | 항목의 swapped 글을 NPC 가 읽는다. 이름 자리는 두 사람이 정한 이름으로 PC 에서 렌더한다 |
| skip | 그 밖의 모든 항목 | NPC 가 안 읽는다. 화면에 글로만 내거나 판이 다른 항목을 쓴다 |

그냥 부르는 말은 넷이다. 이름으로 시작해 쉼표나 느낌표나 물음표로 이어지는 것(Anna, here's your coffee.), 인사나 대답 뒤의 이름(Oh, hi, Pete.), 문장 끝의 쉼표 이름(Thanks, Pete!), Are you 이름? 이다.
자기소개(I'm Anna.), 남을 가리킴(Anna tells Marsha ...), 글자 이야기(Anna with two n's), 소유(Anna's)는 아니다.
이름이 둘 이상이면 어느 쪽이 {A} 인지 못 정해서 skip 이다. 대본 화자 이름이 아닌 것(Ms. Weaver, MINDY)은 이름 자리가 대신 못 해서 skip 이다 (scenes.md 2.1).
swap 은 세 가지가 더 맞아야 한다. 괄호 지시가 없고, 문장이 끝까지 있고(끝이 마침표, 느낌표, 물음표), scenes.md 2.4 막는 말이 없어야 한다. 하나라도 어긋나면 skip 이다.
{A} 와 {B} 는 swap 항목에 id 순으로 번갈아 준다. 무작위가 아니다.

## 7. JSON 짝

`transcripts` `audiolen` `cues` `lecturetext` 는 `.js` 만 있었다. 앱은 `file://` 에서 fetch 가 막혀 `.js` 를 읽는다. 게임은 JSON 을 읽는다.
각 파생기가 `.js` 를 쓰면서 같은 내용의 `.json` 을 같이 쓴다. **`.js` 는 한 글자도 안 바뀐다.** 내용이 같은지는 `check_data.py` 의 짝 검사와 `check_gamedata.py` 의 pairs 규칙이 둘 다 본다.
`out/data/manifest.json` 의 EXPECT 에 네 파일을 더해야 한다 (9장).

## 8. 검사

`scripts/check_gamedata.py` 가 여덟 규칙을 건다. 대본 그대로인지 보는 코드(Verbatim)에도 자체 시험이 있다. `--break` 를 주면 규칙마다 일부러 어긴 자료로 그 규칙이 잡는지 본다. 안 잡는 규칙이 있으면 실패다.

| 규칙 | 보는 것 |
|---|---|
| judge | 판정형 140장이 다 열쇠가 있고 못 읽은 카드가 0이다. 열쇠 없는 카드가 3.2 표와 같다. 통과선과 칸 수와 선택지와 낱말 위치가 맞다 |
| secret | 정답 열쇠가 장면, 응답, 목소리 목록, 덱 이름, 앱 조각에 없다 |
| replies | 역할형 105장이 줄이나 까닭이 있다. 다섯 요소가 있고 이름 자리와 막는 말이 없다 |
| voice | 장면의 NPC 줄 전부와 응답 줄이 목록에 있고 목록의 줄이 어디서 왔는지 거꾸로도 맞다. id 가 해시와 같고 목소리와 빠르기가 5.1 표와 같고 합계가 맞다. 줄에 라디오 인물 이름이 없다 |
| decks | 이름 든 NPC 덱 글마다 처리가 있다. swap 한 글에 이름이 안 남는다. 라디오 구간 판에 글이 없다 |
| pairs | 네 `.js` 와 `.json` 이 같은 내용이다 |
| ground | 응답 줄, 목소리 줄, 바꾼 덱 글이 들은 대본 한 마디 안의 이어진 문장 그대로다. 장면 파생기와 다른 코드로 본다 |
| fresh | 네 JSON 이 원본을 다시 읽은 것과 같다 |

깸 시험 스물일곱: 열쇠 지우기, 못 읽은 카드 적기, 열쇠 없는 카드 늘리기, 짝 고르기에 2 넣기, 통과선 바꾸기, 없는 낱말 넣기, 카드 답을 장면에 싣기, game-only 지우기, 응답 지우기, 줄도 까닭도 없는 응답, 격식 바꾸기, 이름 자리 넣기, 지은 영어 넣기, 안 들은 과로 옮기기, 슬랭 넣기, 장면 줄 빼기, 어디서도 안 온 줄 더하기, id 바꾸기, 목소리 바꾸기, 라디오 이름 남기기, synthetic 거짓, 목록 줄을 지은 영어로, 덱 처리 빼기, 이름 남기기, 대본 json 바꾸기, 강의 본문 json 없애기, 손으로 고친 JSON.

**기계가 안 보는 것: 열쇠가 말의 뜻을 바르게 옮겼는가.** 3.1 표의 근거 문구는 사람이 읽는다.

## 9. 파이프라인에 넣는 법

이 문서의 작업은 `all.py` 와 `derive_manifest.py` 를 안 고쳤다. 그 둘은 다른 손이 맡는다. 넣을 것은 이렇다.

`scripts/all.py` 의 STEPS 에 `derive_scenes.py` 다음, `derive_town.py` 앞에 둔다. check_culture.py 가 `out/game/*.json` 을 훑으므로 그 앞에 와야 옛 값을 안 본다. 모두 브라우저가 필요 없어 빠른 판에도 돈다.

| 묶음 | 스크립트 | 인자 | 빠른 판 |
|---|---|---|---|
| 화면 | derive_judge.py | | 예 |
| 화면 | derive_replies.py | | 예 |
| 화면 | derive_voicelist.py | | 예 |
| 화면 | derive_deck_names.py | | 예 |
| 대조 | check_gamedata.py | --break | 예 |

`scripts/derive_manifest.py` 의 EXPECT 에 `audiolen.json` `cues.json` `lecturetext.json` `transcripts.json` 넷을 더한다. 안 더하면 "적어 두지 않은 파일이 있다" 로 실패한다.
순서는 `derive_replies.py` 가 `derive_voicelist.py` 앞이다. 목소리 목록이 응답 파일을 읽는다.
