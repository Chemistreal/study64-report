# 게임으로 바꾼다. 호놀룰루에서 사는 1년

신뢰도: A 생성 (설계)
상위 규격: docs/spec.md / docs/blocks.md / docs/play_blocks.md
작성일: 2026-10-07

## 1. 결정

**게임이 모든 공부를 대체한다.** 사용자가 2026-10-07 에 정했다.
하루 2시간, 주 엿새, 48주, 288세션이 그대로 게임 속 1년이 된다.

앱(`english.html`)은 두 사람 앞에서 물러난다. 대신 **두뇌로 남는다.**
그날 무엇을 하는지를 정하는 셈과 지금까지 만든 자료가 전부 앱 쪽에 있고,
그것을 게임 안에서 다시 짜면 두 벌이 되고 언젠가 어긋난다 (T396).

    앱의 셈과 자료  ->  out/game/sessions.json  ->  언리얼 게임
                                                     |
    앱의 대장       <-  결과 JSON  <------------------+

게임은 그날 할 일을 스스로 정하지 않는다. **세션 JSON 을 받아서 그린다.**

### 1.1 함께 정한 것 셋 (2026-10-07)

| 결정 | 무엇 |
|---|---|
| **모든 것을 같이** | 하루 2시간 내내 붙어서 **같이 듣고 같이 말하고 같이 한다.** 헤드폰도 대화 금지도 따로 적기도 없다. **두 사람 사이에 가린 것도 없다** (1.3) |
| **다 만들고 시작** | 288세션 장면과 음성과 판단 시스템을 다 만들고 4주 리허설까지 마친 뒤 1일차를 연다 |
| **말은 기계가 판단한다. 넉넉하게** | 두 사람이 한 말을 게임이 듣고 NPC 가 반응한다. 파트너 버튼은 없다 (6장) |
| 녹음은 PC 에만 | 두 사람 목소리는 저장소에 안 들어간다 |

### 1.2 각자 듣기를 없애면서 잃는 것

블록 1 을 각자 둔 까닭이 있었다. 한 사람이 먼저 말해 버리면 다른 사람은
안 듣고 따라간다. 기준서 2.4 가 그것을 **지배-수동형**이라고 부른다.

사용자가 그것을 알고 같이 하는 쪽을 골랐다. 그 자리는 역할 A/B 교대가 지킨다.
날마다 **먼저 말을 여는 사람**이 바뀐다. 그것 말고는 둘이 하는 일이 같다.

### 1.3 정보 격차도 없앤다. 가리는 쪽이 NPC 로 간다

**두 사람 사이에 가린 것이 없다.** 둘이 같은 화면을 보고 같은 말을 듣는다.
사용자가 2026-10-07 에 정했다.

그런데 **정답을 보고 말하면 공부가 안 된다.** 그것은 그대로다.
그래서 가리는 것이 사람 사이에서 **팀과 세상 사이**로 간다.
상황과 정답은 NPC 와 게임이 쥐고 두 사람은 한 팀으로 같이 알아낸다.
판정은 기계가 하니 정답을 볼 사람이 둘 중에 없어도 된다 (6장).

    전에는  A 가 쥐고 B 가 알아낸다
    이제는  NPC 가 쥐고 A 와 B 가 같이 알아낸다

카드의 "판정형 정답은 A면에만" 도 이 꼴로 간다. **두 사람 다 정답을 안 본다.**

놀이 스무 판 중 열셋이 가리기에 기대고 있었다 (`docs/solo_plays.md` 3장).
판마다 이렇게 바뀐다. 이 표가 원본이고 `check_game.py` 가 열셋이 다 있는지 센다.

| 판 | 전에 가린 것 | 이제 |
|---|---|---|
| 거울 | 읽는 쪽만 둘 중 어느 낱말인지 안다 | NPC 가 둘 중 하나를 말한다. 둘이 같이 듣고 어느 쪽인지 고른다 |
| 한 줄 바꾸기 | 읽는 쪽만 바꾼 낱말을 안다 | NPC 가 한 낱말을 바꿔 말한다. 둘이 같이 어디가 바뀌었는지 찾는다 |
| 내 소리는 네가 | 각자 상대 소리의 무엇을 들을지 안다 | 둘이 같이 말하고 게임이 들려준 자리를 같이 다시 말한다 |
| 전달 놀이 | 듣는 쪽만 줄을 듣는다 | NPC 가 한 번 말한다. 둘이 같이 기억해 다른 NPC 에게 전한다 |
| 둘이 한 문장 | 앞뒤 절반을 하나씩 본다 | 앞 절반이 보이고 뒤 절반은 NPC 가 쥔다. 둘이 같이 이어 말한다 |
| 겹치면 지운다 | 각자 적고 같이 편다 | 둘이 같이 적는다. 게임이 대본과 겹친 것을 지운다 |
| 3초 벽 | 띄우는 쪽만 단서를 본다 | 게임이 단서를 띄운다. 3초 안에 둘이 같이 받는다 |
| 한 사람만 본다 | 한 사람만 상황을 안다 | NPC 만 상황을 안다. 둘이 같이 물어 알아낸다 |
| 파장 | 한 사람만 세기를 안다 | NPC 가 세기를 쥔다. 둘이 같이 말하고 NPC 반응으로 맞춘다 |
| 거꾸로 판정 | 판정하는 쪽만 기준을 본다 | 기준이 둘에게 다 보인다. NPC 가 답하고 둘이 같이 판정한다 |
| 못 알아들은 척 | 되묻는 쪽이 줄을 쥔다 | NPC 가 못 알아들은 척한다. 둘이 같이 고쳐 말한다 |
| 어제 그거 | 내는 쪽만 카드를 본다 | NPC 가 어제 카드를 낸다. 둘이 같이 답한다 |
| 따로 쓰고 같이 펴기 | 각자 쓰고 같이 편다 | 둘이 같이 쓴다. 판 이름은 그대로 두되 **같이 쓰기**로 돈다 |

**잃는 것이 있다.** 정보 격차는 "말하지 않으면 못 푼다" 를 만드는 장치였다.
이제 그 압력은 NPC 가 준다. 둘이 알아도 NPC 에게 영어로 말하지 않으면 안 풀린다.

## 6. 말을 듣고 판단하는 시스템

두 사람이 서로에게, 그리고 NPC 에게 한 말을 게임이 듣는다.

| 부분 | 방법 |
|---|---|
| 녹음 | 마이크 둘. 사람마다 따로 받는다. **PC 에만 남는다** |
| 받아쓰기 | 로컬 Whisper 계열 모델. 클라우드를 안 쓴다 |
| 판단 | 받아쓴 말을 **그 장면이 기대하는 말들**과 견준다. 대사가 고정이라 기대도 정해져 있다 |
| 반응 | 알아들으면 진행한다. 못 알아들으면 NPC 가 들은 대본 줄로 다시 해 보자고 한다 ("Let's try that again.", lle1-01). NPC 도 영어를 새로 짓지 않는다 (scenes.md 2장) |

**"Sorry?" 는 NPC 가 안 쓴다.** 52과 대본에 되묻는 꼴로 없기 때문이다. 1세션부터 쓸 수 있는 줄은 1과의 "Let's try that again." 하나고 Daniel 이 1일차에 이미 말한다.
되묻는 줄이 더 들어오는 것은 그 과를 들은 뒤다 ("Excuse me?" 는 lle1-03 을 처음 듣는 148세션부터). 그 전에는 몸짓(귀에 손, 고개 갸웃)이 맡는다.
**두 사람이 "Sorry?" 라고 되묻는 것은 알아듣는다.** 받아들이는 것은 짓는 것이 아니다. 그때 NPC 는 같은 줄을 천천히 다시 말한다.

### 6.1 넉넉하게

**점수를 안 매긴다. 알아들었나만 본다.** 원어민이 듣고 반응하는 것과 같은 자리다.
기대한 말의 핵심 낱말이 들리면 통과로 친다. 어순과 관사와 끝소리가 틀려도 통과다.

넉넉하게 거는 까닭이 있다. **받아쓰기는 한국어 억양의 초급 발음에서 자주 틀린다.**
맞게 말했는데 NPC 가 못 알아듣는 일이 쌓이면 1년을 못 버틴다.
반대로 틀렸는데 통과되는 쪽은 덜 아프다. 되묻기와 다시 말하기가 그 틈을 메운다.

### 6.2 먼저 잴 것

판단 기준은 **두 사람 목소리로 재고 나서** 정한다. 짐작으로 안 정한다.
고정 대사 몇십 줄을 두 사람이 읽어 녹음하고 받아쓰기가 몇 줄을 맞히는지 잰다.
그 숫자가 6.1 의 넉넉함을 정한다.

### 6.3 이것은 무엇을 바꾸나

이 과정은 "앱은 소리를 판정하지 않는다" 를 지켜 왔다 (H단계 결산).
**사용자가 바꿨다.** 기계가 판단한다.

바뀌지 않는 것도 있다. 기계 판단은 **연습 판정**이다. 트랙 통과는 지금처럼
강의가 정한 통과 기준과 그 회차 자료로 매긴다 (개정문 17번).
Q1 소리 트랙 통과는 실제 녹음(C-real)으로만 한다는 9장 규칙도 그대로다.
기계가 판단하는 것은 **두 사람의 목소리**고 기계가 지어낸 소리가 아니다.
