# 하루가 얼마나 걸리나. 블록 3 에 시계가 없다

신뢰도: B (카드 분은 종이 기준 추정이다. 게임에서 재면 짧아질 수 있다. 셈은 기계가 하고 문서의 표는 `scripts/check_curve.py` 가 다시 센 값과 견준다)
검증로그: 2026-10-12 / 사용자 결정 "양이 많아도 돼. 시간 제한 없고, 30분 제한 풀고" 로 블록 3 의 30분 상한을 없앴다. 그 뒤의 하루 길이를 288세션 전부 카드 자료에서 다시 셌다 / 통과 / 하루가 평균 161분이 된다. 받을지는 사용자가 정한다
상위 규격: docs/spec.md 2.3 (개정문 31), docs/game.md 3.0

## 1. 한눈에

블록 3 은 그날 강의 카드(오늘 카드)와 제 날이 된 복습 카드를 다 돌면 끝난다. 쓸 수 있는 분의 상한이 없다.
시간은 **예상 소요**다. 카드마다 적힌 분(`cards.json` 의 `minutes`)을 더한다. 안내이고 상한이 아니다.

| 무엇 | 값 |
|---|---|
| 블록 1, 2, 4 (시계가 있다) | 40분, 30분, 20분. 합 90분. 안 바뀌었다 |
| 블록 3 (시계가 없다) | 세션마다 다르다. 아래 표 |
| 계획 눈금 | 세션 수 x 2시간 = 576시간. 통과선 144/288/432/576 과 등급 구간(`acts.json`)을 센다. **걸린 시간이 아니다** |
| 8.4 의 5회 | 그대로 지킨다. 카드를 지우거나 장수를 줄이지 않았다 |

왜 이렇게 됐나. 8.4 는 카드마다 1년에 다섯 번 이상이라 하고 2.3 은 블록 3 을 30분으로 묶었다. 288세션의 카드 방문을 카드 분으로 더하면 20,460분이다.
블록 3 의 합은 30분 x 288 = 8,640분이었다. 두 줄이 서로 맞지 않았고 30분을 지키면 오늘 카드의 68%가 안 돌았다 (H1 감사 0장 1번, 2번).
사용자가 상한을 풀어서 둘이 같이 선다. 대신 하루가 길다.

## 3. 등급 구간과 실제 시간

`acts.json` 의 등급 구간(A1 1~50, A2 51~100, B1 101~200, B2 201~288)은 **계획 눈금에서 파생**한 그대로다. 이 개정은 구간을 안 옮겼다.
위 표 아래 줄이 실제 누적 시간으로 100, 200, 400, 600시간에 닿는 세션이다. 구간 경계 50, 100, 200 보다 앞선다.
실제 시간으로 구간을 다시 긋는 것은 등급 기준선(케임브리지 안내 학습 시간, B등급 근사)을 어떻게 읽을지의 문제라 사용자 결정으로 남긴다.
다시 그으면 `acts.json` 과 `dataHash` 가 바뀌고 난이도 곡선(`docs/curve.md`)의 구간도 다시 센다.

## 4. 사용자가 정할 것

1. **이 길이를 받을지.** 받으면 지금 그대로다. 못 받겠다면 줄이는 길은 셋이다.
   - 카드 분을 게임에서 잰 값으로 바꾼다. `card_run` 의 `t0` `t1` 에서 배율을 구한다. 배율이 0.7 이면 합이 계획의 116% 로 내려간다.
   - 짧은 날(45분)과 바쁜 날(15분)을 더 자주 쓴다. 제 날이 지난 복습은 지워지지 않고 남는다.
   - 카드 장수나 반복을 줄인다. 8.4 의 5회와 부딪친다. 5회를 최소로 채워도 카드 분이 14,238분이라 블록 3 의 합 8,640분의 1.65배다 (H1 감사 0장 1번). 이 개정문은 이 길을 안 갔다.
2. **등급 구간을 실제 시간으로 다시 그을지** (3장).
3. **하루가 길어 안 하는 날이 늘면.** 기준서 1장은 완주 생존률이 최우선이라 한다. 하루 길이가 완주를 해치면 위 길 중 하나를 쓴다.

## 5. 정직한 한계

| 한계 | 영향 |
|---|---|
| 카드 분은 종이 기준 추정이다 | 모든 분 숫자가 이 값의 배율에 비례한다. 배율 표가 폭을 보인다 |
| 블록 1, 2, 4 가 꽉 찬다고 가정했다 | 실제로는 모자라거나 남는다. 하루 합이 정확한 시간이 아니다 |
| 통과로 가정한 명목 일정이다 | 못 한 카드가 사다리에서 내려가면 복습이 늘어 더 길어진다. 하한이다 |
| 놀이를 안 넣었다 | 블록 3 에 붙은 놀이는 그 분만큼 더한다 |
| 쉬는 날과 시도 횟수를 안 넣었다 | |

## 6. 같이 고친 것

- 기준서 2.3 (개정문 31). 블록 3 시간 칸이 "예상 소요"다. 1장, 2.2, 2.5, 8.4 에 한 줄씩.
- `sessions.json`: `blocks[2].minutes` null, `clock` false. 세션마다 `block3`. 맨 위 `day`. 게임 계약은 `docs/game_results.md` 4.17.
- `check_game.py` 열두째 판: 시계가 자르는 칸이 없고 오늘 카드가 그 강의 카드 전부이며 `block3` 이 다시 센 값과 같다.
- 앱의 블록 3 시계는 끝나도 다음 블록으로 안 넘어간다 (`app/js/08_script.js`).
- 짧은 날은 남겼다. 2시간을 못 내는 날에 두 사람이 고르는 짧은 계획이다. 25분과 20분은 예상 소요(안내)이고 시계로 자르지 않는다 (개정문 32).
