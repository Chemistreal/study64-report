# 1년을 통째로 돈다. 길게 도는 것을 안 재 봤다

신뢰도: A 생성 (검사 설계)
상위 규격: docs/spec.md 2.2 / docs/streak.md / docs/quest.md / docs/ahead.md
작성일: 2026-08-10 (T338)

검증로그: 2026-08-10 / 마흔여덟 주를 하루씩 채워 가며 다시 쟀다 / 통과 / 누적 시간이 손으로 치는 칸이었다

## 1. 한 자리를 재는 검사만 있었다

검사가 서른다섯인데 **다 붙박이 상태를 세워 놓고 한 자리를 잰다.**

    S.days 를 다섯 날로 채운다 → 연속일이 5인가
    20주 자리로 간다 → 신호가 걸리는가

자리마다는 맞는다. 그런데 **마흔여덟 주를 잇달아 갈 때** 어긋나는 것은 안 잡힌다.
빠지는 주, 못 채울 목표, 한 번도 안 도는 값 같은 것들이다.

`scripts/check_year.js` 가 주 1부터 48까지 세션을 채워 가며 그때마다 다시 잰다.
주마다 여섯 판이라 288판이고 거기에 끝과 구간 줄 판정을 더한다.

## 2. 무엇을 재나

| 재는 것 | 왜 |
|---|---|
| 주가 빠짐없이 지나가는가 | 마흔여덟 주가 하나씩 온다. 건너뛰면 그 주 강의가 없어진다 |
| 퀘스트를 채울 수 있는가 | **이상적인 해에도 못 채우면 그것은 못 채울 목표다** |
| 연속일이 안 끊기는가 | 일요일과 비상판 규칙이 1년 내내 맞는가 |
| 든 날이 여섯인가 | 주는 엿새다. 이레째는 점검이라 배정이 없다 |
| 구간 줄이 스물한 주만 뜨는가 | `ahead.md` 가 적은 값과 견준다 |
| 갈래를 다 쓰는가 | 48주 동안 한 번도 안 쓰는 퀘스트 갈래는 죽은 값이다 |
| 1년을 넘기면 무엇을 말하는가 | **끝난 뒤를 아무도 안 봤다** |

### 2.1 이상적인 해로 잰다

하루도 안 빠지고 값도 넉넉히 넣는다. **못 채우는 것을 찾는 검사가 아니다.**
채울 수 있게 만들어 놨는가를 보는 검사다.

밀린 해는 T339 가 잰다. 여기서 둘을 섞으면 못 채운 것이 밀려서인지
목표가 커서인지를 못 가른다.

## 3. 이 검사가 잡은 것. 앱이 아는 것을 사람이 다시 적고 있었다

분기 통과 조건이 분기마다 넷이고 그중 하나가 **누적 시간**이다.
144 / 288 / 432 / 576 시간이 그 선이다.

그 칸이 **손으로 치는 숫자 칸**이었다. 그런데 앱이 이미 안다.
대장 탭이 `totalHours()` 로 그 값을 세어 보이고 있었다.

    앱이 세고 있는 숫자를 옆 탭에서 사람이 다시 친다.

T226 에 주간 점검에서 고친 그 자리와 같은 종류다. 세다가 틀리면 그 분기가 틀리게 남고
배지도 같이 틀린다. **1년을 통째로 돌려 보고서야 보였다.**

### 3.1 나머지 열둘은 그대로 둔다

누적 시간만 앱이 센다. 청취 식별도 무중단 발화도 되묻기 자동화도 **앱이 못 잰다.**
그것까지 자동으로 채우면 그것은 세는 것이 아니라 **지어내는 것**이다.

가르는 자리를 `PASS_AUTO` 한 곳에 뒀다. 거기 없는 것은 사람이 잰다.

### 3.2 값이 한 자리에서만 나온다

`passVal(q, k)` 이 그 자리다. 화면도 배지도 요약도 이것을 쓴다.
셈이 두 자리에 있으면 언젠가 갈린다 (T320, T332 에서 두 번 겪었다).

## 4. 검사가 먼저 틀렸다

처음에 주 w 로 가려고 `w*6` 세션을 채웠다. 그러면 마흔일곱 주가 통째로
"주가 1인데 앱은 2라고 한다" 로 나왔다.

**끝낸 수로 세는 값은 끝나는 순간 다음을 가리킨다.** T316 과 T325 에서 두 번 적어 둔 것이다.
여섯 세션을 마치면 1주가 끝난 것이고 서 있는 자리는 2주 첫날이다.

주 w 첫날에 서려면 `(w-1)*6` 이다. **앱이 맞았고 검사가 틀렸다.**
새 검사가 처음 내는 실패는 검사 자신을 먼저 의심한다. 열두 번째다.

## 5. 기계가 안 보는 것

마흔여덟 주를 진짜로 견디는지는 이 검사가 못 잰다.
채울 수 있는 목표라는 것과 채우게 되는 목표라는 것은 다르다.

기계가 재는 것은 **셈이 1년 내내 안 어긋나는가**뿐이다.
