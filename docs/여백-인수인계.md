### 2-1. PC 오디오 만들기 (37강을 빠르게)
```powershell
cd reader\pc-tool
npm install                         # onnxruntime-node 1.20.1 (윈도우 DirectML 포함)
node make-audio.mjs ..\library\통찰력-시즌2-49-82강.zip --voice M1 --size normal
#   --voice F1|F2|F3|M1|M2|M3   (미나·소라·유나·에이든·히로·레오)
#   --size  small(약 7MB/시간) | normal(약 11MB/시간) | high(약 21MB/시간)
#   --steps 5~12 (기본 8, 적을수록 빠름) · --cpu (GPU 안 씀) · --out 출력 폴더
```
- 처음 실행할 때 모델(약 380MB)을 `%USERPROFILE%\.yeobaek-ai\supertonic-3`에 받습니다. 끊겨도 이어 받습니다.
- 윈도우에서는 DirectML(GPU)을 먼저 시도하고, 실패하면 CPU 전체 코어로 넘어갑니다. 화면에 "GPU(DirectML)" 또는 "CPU"와 배속이 찍힙니다.
- 결과: `yeobaek-audio-out\yeobaek-ai-audio-날짜.zip`(140MB마다 나뉨)과 강의별 `mp3\`. 다시 실행하면 이미 만든 강의는 건너뜁니다.
- 아이폰으로 ZIP을 보낸 뒤(에어드롭 · 카카오톡 나에게 · iCloud), 여백 서재 입력창 **+** 버튼으로 고르면 강의마다 오디오와 문단 위치가 붙습니다.
- 다른 TTS 프로그램으로 만든 MP3도 `글.md` + `글.mp3`(같은 이름)를 ZIP으로 묶어 **+**로 올리면 붙습니다(PR #48 머지 후).

### index.html에서 자주 만지는 함수
- **재생**: `startSpeech` → (미리 만든 오디오) / `startLiveAi`(실시간 AI) / `speakBlock`(기기 음성). AI가 준비되기 전에는 `beginAiBridge` → `switchBridgeToAi`.
- **실시간 AI**: `pumpLive`, `playNextLive`, `armLiveWait`, `liveClipGet/Put`(최근 10분 재사용), `updateLiveStatus`, `holdScreenOn`.
- **책 끝**: `bookFinished` → 그 책에서 멈춤. 다음 책 자동 이어 듣기와 취침 "이 책이 끝나면"은 #65에서 삭제(사용자 요청).
- **AI 대기열**: `runLocalAiQueue`, `nextQueuedAiJob`, `aiBatchesForBook`(700자 조각), `aiChunkId`(조각 이름에 용량 단계 포함), `audioTimeline`, `aiStorageRoom`, `aiPausedByScreen`(휴대폰만 화면 꺼지면 쉼).
- **버튼과 패널**: `aiBookButton`, `renderAiBookPanel`, `aiBookStageText`, `aiBookWaitReason`.
- **보내기/가져오기**: `exportAiAudioPack`, `importAiAudioPack`, `importTextAudioPairs`, `bookHash`(본문 SHA-256).
- **복구**: `checkAiLoadCrash`(메모리에 올리다 죽음 → 다음엔 CPU·1코어·기기 음성), `repairSilentAiAudio`(무음 MP3 찾아 다시 만들기), `resumeModelDownload`.
- ⚠ `normalizeBlocks`, `blocksFromText`는 **반드시 한 줄짜리 최상위 함수로 유지**해야 합니다. PC 프로그램이 이 두 줄을 읽어 같은 문단 규칙을 씁니다. `tests/pc-tool-check.js`가 이를 지킵니다.

## 4. 데이터 형식

- **IndexedDB 저장소**: `books`, `meta`(settings · 대기열 · composerDraft · `aiLoadingSince`), `audio`, `audioPositions`, `trash`, `sources`, `aiParts`(AI 조각 체크포인트).
- **audio 레코드**: `{id(=책 id), blob, name, aiVoice?, generatedAt?, timeline?:[[문단번호, 초]...], timelineDuration?}`. `aiVoice`가 있으면 AI 오디오입니다. 재생할 때 시간표는 실제 길이/`timelineDuration` 비율로 보정합니다.
- **AI 오디오 꾸러미 ZIP**: `yeobaek-ai-audio.json` = `{format:'yeobaek-ai-audio', version:1, items:[{title, type, hash, blocks, aiVoice, name, timeline, timelineDuration, path:'audio/N.mp3'}]}` + `audio/N.mp3`. 가져올 때는 `hash`로 같은 글을 찾고, 없으면 `blocks`로 책을 만듭니다. 문단 수가 다르면 시간표를 버립니다.
- **글+MP3 세트 ZIP**: 확장자를 뺀 경로가 같은 글(.md/.txt/…)과 오디오(mp3/m4a/aac/wav/ogg/opus)를 짝짓습니다.
- **설정 키**: `aiLive`, `aiConsent`, `aiVoice`, `aiAuto`, `aiQuality`(fast/normal/high → 5/8/12단계), `aiDevice`(auto/gpu/cpu), `aiAudio`(small/normal/high), `aiThreads`, `keepScreenOn`.
- **Cache Storage**: `yeobaek-ai-model-v1`(모델, 조각 `?yb-part=N`, `?yb-meta`), `yeobaek-ai-runtime-v1`(onnxruntime-web 1.17.3 CDN 파일), `yeobaek-reader-shell-v2`.

## 5. 꼭 알아야 할 함정

1. **lamejs 무음 버그**: 비트레이트에 비해 표본율이 높으면 lamejs가 내부에서 표본율을 다시 낮추는데, 이때 소리가 거의 사라집니다.
   - 실측(사인파 기준, 정상 -17dB): 44.1kHz·48kbps → -37dB(실제로는 32kHz로 저장), 22.05kHz·24kbps → -49dB.
   - 정상 조합: 16kHz는 전부, 22.05kHz는 32kbps 이상, 44.1kHz는 64kbps 이상.
   - 그래서 표본율을 직접 낮춘 뒤 `small 16k/16 · normal 16k/24 · high 22.05k/48` 조합만 씁니다.
   - **바꾸면 `tests/reader-ai-audio-quality.js`로 반드시 확인하세요.**
2. **onnxruntime-web 1.17.3 + 최신 크롬**: 엔진이 없어진 `GPUAdapter.requestAdapterInfo()`를 불러 WebGPU를 조용히 포기합니다. `aiModule()`에서 `adapter.info`로 채워 주는 코드가 있습니다. 엔진 버전을 올리면 이 코드를 빼도 됩니다.
3. **멀티코어**: GitHub Pages는 헤더를 못 바꿔서 `sw.js`의 `isolate()`가 COOP/COEP를 붙입니다. 두 번째 방문부터 `crossOriginIsolated`가 켜집니다. 바깥 자원(Google Fonts, jsdelivr, cdnjs, Hugging Face)은 모두 CORS/CORP를 보냅니다. 새 바깥 자원을 넣으면 CORP/CORS를 확인하세요. tesseract OCR은 격리 상태에서 실제 확인을 아직 못 했습니다.
4. **아이폰 제약**:
   - 화면이 꺼지면 웹 계산(AI)이 멈춥니다. 잠금 화면에서 확실히 이어지는 건 미리 만든 오디오 파일뿐입니다.
   - 실시간 AI는 탭하는 순간 무음 재생으로 오디오 요소를 깨워 두고, 화면 켜 두기와 무음 유지(최대 30분)로 버팁니다.
   - 처음 AI 모델을 메모리에 올릴 때 큰 모델(vector_estimator 245MB)이라 아이폰이 죽을 수 있습니다. 그래서 멈춤 감지와 기기 음성 대체가 있습니다.
5. **테스트 하네스**: 많은 테스트가 `window.aiModule`을 가짜로 바꿔 진행합니다. 실제 모델 검증은 수동 스크립트(아래 6)로 했습니다.
6. **도구 검사**: 사용자에게 보이는 문구를 바꾸면 `tools/msg_ledger.py`, 브라우저 저장 키를 바꾸면 `tools/store_ledger.py`로 확인합니다.

## 6. 실측 기록 (클라우드 4코어 공유 서버, 실제 Supertonic-3)

- 브라우저 WASM 1코어: 5.6초 문장을 9.9초에 만듦(0.57배속). 3코어(격리): 5.2초(1.08배속). 모델 불러오기 약 18~20초.
- Node.js(onnxruntime-node CPU, PC 프로그램): **3.4배속**.
- 용량(1시간 분량): small 6.9MB · normal 10.4MB · high 20.7MB. 37강(약 37시간)이면 normal 기준 약 390MB.
- WebGPU는 이 환경에 GPU가 없어 가상 GPU로만 경로를 확인했습니다. 실제 속도는 미측정입니다.
