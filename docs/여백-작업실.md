# 여백 작업실 (PC → AI 오디오 책 → 여백 리더)

PC에 글을 올리면 **원문+AI 오디오 ZIP**을 만들고, 여백 리더의 **추천 글**에 자동으로 올리는 시스템입니다.

```
글(.md/.txt) ──▶ 여백 작업실(PC, http://127.0.0.1:7788)
                 ├─ Edge 신경망 음성 '현수'로 문단마다 받기(동시 요청, 끊기면 다시 받기, 이어 만들기)
                 ├─ ffmpeg로 이어 붙여 MP3 하나 + 문단 시간표
                 ├─ out\제목.zip            ← 원문+오디오 ZIP(여백 + 버튼으로 바로 가져옴)
                 └─ site\books\<id>\        ← book.json + 19MB 조각 MP3
                          │ 자동 올리기(gh 로그인)
                          ▼
   GitHub 저장소 Chemistreal/yeobaek-audio → https://chemistreal.github.io/yeobaek-audio/
                          │ 같은 사이트(chemistreal.github.io)라 그대로 받음
                          ▼
   여백 리더 '추천 글' → '오디오와 함께 담기' → 조각을 받아 잇고 글·시간표와 함께 서재에
```

## 결정 사항
- 리더 안의 **기기 AI 목소리(Supertonic, 380MB 모델)는 뺐습니다**(2026-11-12). 아이폰에서 모델을 불러오다 멈추는 일이 잦았고 한국어가 어색했습니다.
  AI 낭독은 이 작업실이 만든 오디오 책으로 듣고, 오디오가 없는 책은 기기 음성으로 읽습니다. 예전에 받아 둔 모델·조각은 리더가 열릴 때 지웁니다(`cleanupDeviceAi`).
- 아이폰: 추천 글 → '오디오와 함께 담기' → 책 열기 → 읽어주기 → **지금 읽는 문단부터** 재생, 소리를 따라 문단 표시가 움직임, 문단을 누르면 그 자리로 이동, 화면을 잠가도 이어짐.
- 책 1권 = 글 파일 1개(통합본도 통째로 1권).
- 목소리: Microsoft Edge 신경망 음성 **현수**(`ko-KR-HyunsuMultilingualNeural`). API 키 없음, 인터넷 필요.
  - Supertonic-3(기기 안 AI)는 한국어가 어색해서 PC 작업실에서는 쓰지 않습니다. Qwen3-TTS·CosyVoice3도 비교 후 뺐습니다.
- 기본 **1.5배속**(AI가 처음부터 빠르게 말함 — 재생 속도를 올리는 것과 달리 소리가 늘어지지 않음), 음질 **좋게(24kHz·48kbps, 현수 원음 그대로, 시간당 약 20.6MB)** — 2026-11-13부터. 아이폰 리더 설정의 ‘현수 오디오 모두 고음질로 바꾸기’는 예전 오디오(작게)를 `inbox/<id>-hq.json`으로 다시 만들어 받아 바꿔 끼운다.
- 설치·작업 파일은 전부 **D 드라이브** `D:\yeobaek-studio`(D가 없으면 사용자 폴더).
- 오디오는 리더 저장소(study64-report, 앱 4개가 Pages 1GB를 함께 씀)가 아니라 **오디오 전용 저장소**에 둡니다. 올릴 때마다 기록을 한 장으로 다시 써서 지운 오디오가 쌓이지 않습니다.

## 아이폰에서 담은 책도 현수 오디오로 (GitHub Actions, PC 꺼져 있어도 됨)
```
아이폰 리더: 책 관리 → '현수 오디오 만들기' (또는 '새로 담는 책은 자동으로' 켜기, 여러 권 선택 → '현수 오디오')
   │ GitHub 키(오디오 저장소 Contents 읽기·쓰기만)로 inbox/<id>.json 에 글(문단 그대로) 올림
   ▼
yeobaek-audio의 .github/workflows/site.yml (audio-site/site.yml에서 복사)
   │ inbox-build.mjs: 요청마다 Edge 현수 1.5배로 만들어 books/ 에 넣고 바로 올림 → GitHub Pages 배포
   ▼
아이폰 리더(열려 있을 때 1분마다): 목록에 같은 본문 해시(<id>)의 책이 생기면 받아서 그 책에 붙임 · 실패하면 카드에 이유
```
- 키 만드는 법: 리더 설정 → AI 오디오 책 → 'GitHub 키 만드는 법'. 키는 이 기기의 서재 저장소(meta `githubAudioKey`)에만 두고 설정·백업에 넣지 않습니다.
- **보낸 글은 공개 저장소에 올라갑니다.**
- 올리기(`publish.mjs` `syncPush`)는 '원격 최신 상태 위에 바꿀 것만 얹기'라 PC 작업실·아이폰 요청·Actions가 서로의 책을 지우지 않습니다(`tests/audio-repo-sync.js`). PC는 기록을 한 장으로 다시 쓰고, Actions는 이어 붙입니다(기본 토큰은 워크플로 파일을 바꾸는 push를 못 하므로).
- GitHub 서버에서도 Edge 현수 음성이 됩니다(2026-11-12 시험: 동시 10개 모두 성공).
- 요청은 **짧은 글부터** 하나씩 만듭니다(강의 하나 약 3~7분, 100만 자 묶음은 약 2시간). 실행 중에 들어온 요청은 다음 실행이 맡습니다(동시에 하나만 돌고, 기다리는 실행은 가장 최근 것 하나만 남음).

## 설치와 실행 (윈도우)
```powershell
irm https://chemistreal.github.io/study64-report/reader/pc-tool/setup.ps1 | iex   # 처음 한 번
gh auth login                                                                       # 올리기용, 처음 한 번
D:\yeobaek-studio\app\pc-tool\studio.cmd                                            # 작업실 열기
```
저장소 사본에서 바로 열 때: `node reader\pc-tool\studio.mjs`.
명령줄: `node reader\pc-tool\make-audio.mjs 글.md --speed 1.5 --size small --jobs 10`.

## 데이터 형식
- 오디오 저장소 `index.json`: `{format:'yeobaek-audio-shelf', version:1, updated, items:[{id, title, description, manifest:'books/<id>/book.json', bytes, duration, chars, speed, profile, published}]}`
- `books/<id>/book.json`: AI 오디오 꾸러미와 같은 항목(`title, type, hash, blocks, aiVoice:'Hyunsu', timeline, timelineDuration`) + `audio:{parts:['audio.001.mp3',…], bytes, type}`
- `<id>` = `b-` + 본문 해시 앞 12자리. 같은 글을 다시 올리면 바뀝니다.
- 리더는 같은 글(본문 해시)이 서재에 있으면 그 책에 오디오를 붙이고, 없으면 새 책을 만듭니다.

## 함정
- 32kHz MP3는 쓰지 않습니다. 리더가 예전 무음 버그 파일(MPEG-1 32kHz)로 보고 지웁니다(`isSilentLameMp3`).
- Edge '현수'는 요청이 가끔 중간에 끊기거나 소리 없이 끝납니다. `edge_book.py`가 문장 경계 정보로 85% 이상 읽혔는지 보고 다시 받습니다.
- 현수는 요청 하나가 느려서 동시 요청 4개면 1분에 약 10문단, 10개면 약 80문단입니다(2026-11-12 실측). 작업실 기본값은 4, 화면에서 바꿀 수 있습니다.
- GitHub Pages 한도 1GB: 작업실이 950MB에서 멈춥니다. 오래된 책은 작업실에서 '사이트에서 내리기'.
- Edge 음성은 마이크로소프트의 공개 낭독 서비스를 쓰는 비공식 방법입니다. 막히면 다른 음성으로 바꿔야 합니다(`edge_book.py`만 바꾸면 됨).
- 아이폰 홈 화면 웹앱은 잠금 화면에서 '일시정지 → 다시 재생'이 안 먹는 WebKit 버그가 있습니다(WebKit 243258). 리더는 재생 중이 될 때마다 잠금 화면 조작을 다시 등록하고, 10분 넘게 멈췄거나 재생이 거부되면 저장된 오디오를 다시 불러와 같은 자리부터 잇습니다(`resumeAttachedAudio`, 테스트 `tests/reader-lockscreen-audio.js`). 실측: 멈춘 지 3초는 되고 5초부터 거부됨(2026-11-12) → 화면이 꺼진 채 누른 일시정지는 같은 오디오 요소로 무음 소리를 반복 재생하며 위치를 기억합니다(`softPauseAudio`, 30분 뒤 진짜 멈춤, 앱으로 돌아오면 진짜 일시정지). 음소거로 하면 안 됩니다: iOS가 음소거된 소리는 재생 중으로 치지 않아 10초쯤 뒤 잠금 화면 정보가 사라집니다(실측).
